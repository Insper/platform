Index

In this lab

  • Add five AI steps to the BoxOffice pipeline of lab 11: a pull-request reviewer, a test generator checked by mutation testing, an agent that proposes a fix when CI fails, release notes on every tag, and an explained canary verdict.
  • Run every step through one small, provider-neutral client: a local model with Ollama (free, the default), Claude through the official SDK, or any OpenAI-compatible endpoint through LiteLLM.
  • Harden the workflows: permissions, triggers, secrets, and a prompt-injection test that the reviewer must survive.
  • Measure it: review precision, cost per PR, CI minutes and time to merge over a week of pull requests.

Lab 11 gave BoxOffice a pipeline that builds, tests, scans, signs and rolls out each change behind a canary. Lab 12 put a language model inside the product. This lab puts language models inside the pipeline — and treats them with the same discipline as any other dependency: least privilege, budgets, validation of every output, and numbers that say whether they help. In the story of the course it builds chapter 14: the decisions of code review, AI-generated tests, agents in CI, release and operate and security & governance.

The rule for the whole lab: AI proposes, rules and humans dispose. No step in this lab can merge, approve, deploy or roll back on its own. The model writes comments, patches and explanations; deterministic checks (tests, mutation score, policy thresholds) and people decide.

0. Setup: one client, three ways to reach a model

All scripts live in .github/ai/ of your repository and import one module, llm.py. It hides the provider behind a single function, complete_json(system, user, schema), that returns JSON validated against a schema plus the token usage and its cost. The provider is chosen with environment variables — the same names locally and in GitHub Actions (as repository variables):

Variable Default Meaning
LLM_PROVIDER ollama ollama (local, free), anthropic (Claude) or openai (any OpenAI-compatible endpoint, e.g. LiteLLM)
LLM_MODEL qwen2.5-coder-16k on ollama, claude-opus-5-5 on anthropic the model id
LLM_BASE_URL http://localhost:11434/v1 on ollama endpoint of ollama / openai
LLM_API_KEY, ANTHROPIC_API_KEY — secrets, only for the paid or remote paths

0.1 Pick a model

  1. Install Ollama and start it:

    # macOS
brew install ollama && brew services start ollama
# Linux and Windows (inside WSL 2)
curl -fsSL https://ollama.com/install.sh | sh

    Check that the server answers: curl -s http://localhost:11434/api/version prints {"version":"..."}. On Linux without systemd (some WSL setups), start it by hand in another terminal with ollama serve.

  2. Get the model — after you saved the files of step 0.2 (the script is one of them):

    bash .github/ai/ollama-model.sh

    It downloads qwen2.5-coder:7b (4.7 GB, once) and creates qwen2.5-coder-16k, the same model with a 16,384-token context window. Ollama's default window is 4,096 tokens, and a longer prompt is cut silently — the reviewer would lose its instructions on a big diff. You should see, at the end:

    success
ready: LLM_PROVIDER=ollama LLM_MODEL=qwen2.5-coder-16k (context 16384 tokens)

Nothing else to configure: ollama is the default provider. In GitHub Actions the workflows install Ollama on the runner with the composite action .github/actions/ollama (below) — free, but slow: a CPU-only runner needs minutes per call, where your laptop needs seconds. Expect lower review quality than a frontier model; part 6 measures how much lower.

  1. Create an API key in the Claude Console and set a monthly spend limit for its workspace (a few dollars is plenty for this lab).
  2. Locally: export LLM_PROVIDER=anthropic and export ANTHROPIC_API_KEY=<the key you just created> (never commit it; the lab 0 .gitignore already ignores .env).

  3. In GitHub: Settings → Secrets and variables → Actions, or with gh:

    gh secret set ANTHROPIC_API_KEY          # paste the key when asked
gh variable set LLM_PROVIDER --body anthropic
gh variable set LLM_MODEL --body claude-opus-5-5   # or claude-sonnet-5-5 / claude-haiku-4-5: cheaper

The client calls the Messages API through the official anthropic SDK with structured outputs (output_config.format with a JSON schema), prompt caching of the system prompt, and the server-side refusal fallback (a beta) on models that support it. Check the models overview for current model ids and prices.

The LiteLLM proxy of lab 12 exposes an OpenAI-compatible endpoint in front of any provider. Locally: export LLM_PROVIDER=openai LLM_BASE_URL=http://localhost:4000/v1 LLM_MODEL=<a model alias of your proxy> and export LLM_API_KEY=<your LiteLLM virtual key>; curl -s -H "Authorization: Bearer $LLM_API_KEY" $LLM_BASE_URL/models lists the aliases.

GitHub-hosted runners cannot reach localhost on your laptop: in CI this path needs a LiteLLM proxy reachable from the internet (or a self-hosted runner). Set the repository variables LLM_PROVIDER=openai, LLM_BASE_URL, LLM_MODEL and the secret LLM_API_KEY (a virtual key with its own budget).

What about GitHub Models?

Earlier versions of this lab could use GitHub Models, a free inference API for Actions. GitHub retired it on 30 July 2026 (GitHub docs), so the free path is now Ollama.

What costs money

Item Cost
Ollama on your machine free (electricity, ~5 GB of disk)
GitHub Actions minutes free for public repositories; in a private repository they count against your plan's monthly minutes (GitHub billing) — the Ollama path uses several runner minutes per AI job
Claude API (LLM_PROVIDER=anthropic, and path A of part 3) paid per token; protect it with a workspace spend limit. Each job prints its cost in US$
A LiteLLM proxy on the internet whatever its upstream provider charges

Course policy for this lab

Use your own key or a local model, never a teammate's or a company's. Never paste secrets, real customer data or personal data into prompts. Any commit that contains AI-generated code carries the trailer AI-assisted: <tool> (<model>) and every AI-opened PR carries the label ai-generated.

#!/usr/bin/env bash
# Prepare the free local model of lab 13 (run it from the repository root):
#
#     bash .github/ai/ollama-model.sh
#
# Pulls qwen2.5-coder:7b (4.7 GB) and creates `qwen2.5-coder-16k`: the same weights with a
# 16,384-token context window. Ollama's default window is 4,096 tokens, and a longer prompt
# (conventions + a big diff, or an agent's growing conversation) is cut SILENTLY.
set -euo pipefail

BASE="${OLLAMA_BASE_MODEL:-qwen2.5-coder:7b}"
NAME="${OLLAMA_MODEL_NAME:-qwen2.5-coder-16k}"
CTX="${OLLAMA_NUM_CTX:-16384}"

ollama pull "$BASE"
modelfile="$(mktemp)"
printf 'FROM %s\nPARAMETER num_ctx %s\n' "$BASE" "$CTX" > "$modelfile"
ollama create "$NAME" -f "$modelfile"
rm -f "$modelfile"
echo "ready: LLM_PROVIDER=ollama LLM_MODEL=$NAME (context $CTX tokens)"

"""Provider-neutral LLM client for the BoxOffice CI jobs.

LLM_PROVIDER=ollama     (default) a local model through Ollama's OpenAI-compatible API: free, no key
                        (LLM_BASE_URL defaults to http://localhost:11434/v1)
LLM_PROVIDER=anthropic  Claude Messages API through the official SDK (needs ANTHROPIC_API_KEY)
LLM_PROVIDER=openai     any other OpenAI-compatible endpoint, e.g. a LiteLLM proxy
                        (needs LLM_BASE_URL; LLM_API_KEY if the endpoint wants one)
LLM_MODEL               model id: qwen2.5-coder-16k (see ollama-model.sh), claude-opus-5-5, ...

Every call returns parsed JSON that validates against a JSON Schema, plus the token
usage, so each job can print what it cost.
"""
from __future__ import annotations

import json
import os
import sys
import time
from dataclasses import dataclass

import jsonschema

# US$ per million tokens: (input, output, cache read). List prices when this lab was
# written -- illustrative; check the provider's pricing page. Unknown models cost 0 here
# (a local Ollama model costs runner minutes, not tokens).
PRICES = {
    "claude-opus-5-5": (4.00, 20.00, 0.20),
    "claude-sonnet-5-5": (2.00, 10.00, 0.20),
    "claude-haiku-4-5": (1.00, 5.00, 0.10),
}
CACHE_WRITE = 1.25  # a 5-minute cache write costs 1.25x the input price
# Models that accept the server-side refusal fallback (beta); see the Claude docs.
FALLBACK_MODELS = {"claude-opus-5-5", "claude-sonnet-5-5"}


class LLMError(RuntimeError):
    """The model did not return a usable answer (refusal, truncation, invalid JSON)."""


@dataclass
class Usage:
    model: str
    input_tokens: int = 0        # uncached input
    cache_read_tokens: int = 0
    cache_write_tokens: int = 0
    output_tokens: int = 0       # includes thinking tokens, billed as output
    calls: int = 0
    seconds: float = 0.0

    def add(self, other: "Usage") -> None:
        for f in ("input_tokens", "cache_read_tokens", "cache_write_tokens",
                  "output_tokens", "calls", "seconds"):
            setattr(self, f, getattr(self, f) + getattr(other, f))

    @property
    def usd(self) -> float:
        price = PRICES.get(self.model)
        if price is None:
            return 0.0
        p_in, p_out, p_read = price
        return (self.input_tokens * p_in + self.cache_write_tokens * p_in * CACHE_WRITE
                + self.cache_read_tokens * p_read + self.output_tokens * p_out) / 1e6

    def as_dict(self) -> dict:
        return {"model": self.model, "calls": self.calls, "in": self.input_tokens,
                "cache_read": self.cache_read_tokens, "cache_write": self.cache_write_tokens,
                "out": self.output_tokens, "seconds": round(self.seconds, 1),
                "usd": round(self.usd, 4)}

    def markdown(self) -> str:
        price = "n/a (local or unknown model)" if self.model not in PRICES else f"US$ {self.usd:.4f}"
        return ("| Model | Calls | Input | Cache read | Cache write | Output | Time | Cost |\n"
                "|---|---|---|---|---|---|---|---|\n"
                f"| `{self.model}` | {self.calls} | {self.input_tokens:,} | {self.cache_read_tokens:,}"
                f" | {self.cache_write_tokens:,} | {self.output_tokens:,} | {self.seconds:.1f} s"
                f" | {price} |\n")


def provider() -> str:
    return os.environ.get("LLM_PROVIDER") or "ollama"     # the free path is the default


def model() -> str:
    default = "qwen2.5-coder-16k" if provider() == "ollama" else "claude-opus-5-5"
    return os.environ.get("LLM_MODEL") or default


def base_url() -> str:
    """Endpoint of the OpenAI-compatible providers (ollama, openai)."""
    url = os.environ.get("LLM_BASE_URL") or (
        "http://localhost:11434/v1" if provider() == "ollama" else "")
    if not url:
        raise LLMError("LLM_PROVIDER=openai needs LLM_BASE_URL (e.g. http://localhost:4000/v1)")
    return url


def complete_json(system: str, user: str, schema: dict, *, max_tokens: int = 16000,
                  effort: str = "medium") -> tuple[dict, Usage]:
    """One model call that must answer with JSON valid against `schema`.

    `system` should be stable across runs (it is cached); `user` carries the data
    of this run (diff, logs, metrics), which is untrusted.
    """
    start = time.monotonic()
    try:
        if provider() == "anthropic":
            data, usage = _anthropic(system, user, schema, max_tokens, effort)
        else:
            data, usage = _openai_compatible(system, user, schema, max_tokens)
    except LLMError:
        raise
    except Exception as err:  # no key, connection refused, quota... -> the caller fails open
        raise LLMError(f"{type(err).__name__}: {str(err)[:300]}") from err
    usage.seconds = time.monotonic() - start
    return data, usage


def _anthropic(system, user, schema, max_tokens, effort):
    import anthropic

    client = anthropic.Anthropic()          # reads ANTHROPIC_API_KEY
    name = model()
    output_config = {"format": {"type": "json_schema", "schema": schema}}
    if "haiku" not in name:                 # the effort parameter is not available on Haiku 4.5
        output_config["effort"] = effort
    request = dict(
        model=name,
        max_tokens=max_tokens,
        # The system prompt (instructions + conventions) is the same on every run:
        # mark it for prompt caching so repeated runs pay the cheap cache-read price.
        system=[{"type": "text", "text": system, "cache_control": {"type": "ephemeral"}}],
        messages=[{"role": "user", "content": user}],
        output_config=output_config,
    )
    if name in FALLBACK_MODELS:
        # If a safety classifier declines the request, the API re-runs it on a fallback model.
        response = client.beta.messages.create(
            betas=["server-side-fallback-2026-07-01"], fallbacks="default", **request)
    else:
        response = client.messages.create(**request)

    if response.stop_reason == "refusal":
        raise LLMError("the model declined the request")
    if response.stop_reason == "max_tokens":
        raise LLMError("answer truncated: raise max_tokens or send less context")
    text = next((b.text for b in response.content if b.type == "text"), "")
    data = _parse(text, schema)
    u = response.usage
    usage = Usage(name, input_tokens=u.input_tokens,
                  cache_read_tokens=u.cache_read_input_tokens or 0,
                  cache_write_tokens=u.cache_creation_input_tokens or 0,
                  output_tokens=u.output_tokens, calls=1)
    return data, usage


def _openai_compatible(system, user, schema, max_tokens):
    from openai import OpenAI

    client = OpenAI(base_url=base_url(), api_key=os.environ.get("LLM_API_KEY") or "not-needed")
    name = model()
    # JSON mode is widely supported (LiteLLM, Ollama, vLLM); the schema goes in the
    # prompt and the answer is validated here, with one repair attempt.
    instructions = (system + "\n\nAnswer with ONE JSON object, and nothing else, that validates "
                    "against this JSON Schema:\n" + json.dumps(schema))
    messages = [{"role": "system", "content": instructions}, {"role": "user", "content": user}]
    usage = Usage(name)
    for attempt in range(2):
        response = client.chat.completions.create(
            model=name, max_tokens=max_tokens, temperature=0,
            response_format={"type": "json_object"}, messages=messages)
        usage.calls += 1
        if response.usage:
            usage.input_tokens += response.usage.prompt_tokens
            usage.output_tokens += response.usage.completion_tokens
        text = response.choices[0].message.content or ""
        try:
            return _parse(text, schema), usage
        except LLMError as err:
            if attempt == 1:
                raise
            messages += [{"role": "assistant", "content": text},
                         {"role": "user", "content": f"Invalid answer: {err}. Reply again with "
                                                     "only the JSON object."}]
    raise AssertionError("unreachable")


def _parse(text: str, schema: dict) -> dict:
    try:
        data = json.loads(text)
        jsonschema.validate(data, schema)  # defence in depth, even with structured outputs
    except (json.JSONDecodeError, jsonschema.ValidationError) as err:
        raise LLMError(f"answer is not valid JSON for the schema: {str(err)[:200]}") from err
    return data


def step_summary(markdown: str) -> None:
    """Append Markdown to the job summary page (or print it when running locally)."""
    path = os.environ.get("GITHUB_STEP_SUMMARY")
    if path:
        with open(path, "a", encoding="utf-8") as f:
            f.write(markdown + "\n")
    else:
        print(markdown, file=sys.stderr)

What to notice in llm.py:

Design decision Why
system is stable, user carries the run's data The system prompt (instructions + conventions) is identical on every run, so it can be cached: on Claude, cached input tokens are billed at a fraction of the normal price. The diff, logs and metrics change every run and go in user.
Structured output + schema validation Claude constrains the answer to the JSON schema (output_config.format); the OpenAI-compatible path (Ollama, LiteLLM) uses JSON mode and validates with one repair attempt. Either way the caller gets a dict it can check, never free text it must parse.
Every failure becomes an LLMError A refusal, a truncated answer (max_tokens), no API key, a model server that is down: each job decides explicitly what happens then (usually: fail open, skip the AI step and say so in the summary).
Usage with prices Every job prints tokens and dollars in its summary. You cannot manage a cost you do not see. The prices are list prices when this lab was written — update PRICES from the provider's page. A local model shows n/a.
No retries here The SDKs already retry 429 and 5xx with backoff; a second retry layer would multiply calls during an outage (the retry storm of Reliability).

0.3 The context: conventions and decisions

The reviewer is only as good as what it knows about your system. A generic model knows Java; it does not know that order must never write to the inventory schema. Write that knowledge down once — for humans first — in CONVENTIONS.md at the root of the repository:

CONVENTIONS.md
# BoxOffice conventions

Read by humans and by the AI reviewer. Keep it short: every line costs tokens on every review.

## Architecture rules (blocker if violated)
- One PostgreSQL schema per service (`catalog`, `inventory`, `orders`, `payment`, ...).
  A service reads and writes ONLY its own schema. Another service's data is reached
  through its HTTP API or its events, never with SQL.
- Seat state (holds, sales) is owned by `inventory`. Any change to a seat goes through
  inventory, inside a transaction that locks the row (`SELECT ... FOR UPDATE`) or uses
  optimistic locking. Double booking is the worst bug this system can have.
- `order` publishes events through the transactional outbox, never directly to Kafka
  inside a database transaction.
- Every outbound HTTP call (service-to-service or to the payment provider) has a connect
  and a read timeout, and calls to `payment` are idempotent (Idempotency-Key header).
- Services trust identity only from the `X-User-*` headers set by the gateway.

## Code
- Java 21, Spring Boot 4.1, Spring Cloud 2025.1; DTOs are `record`s; no Lombok.
- Money is `long` cents or `BigDecimal`, never `double`.
- SQL uses bind parameters; never build SQL by string concatenation.
- No secrets in code or in application.yaml: read them from environment variables.
- Errors are RFC 9457 problem+json; `POST` that creates returns 201 with `Location`.
- Flyway migrations are append-only: never edit a migration that was merged.

## Tests
- Business rules in `inventory`, `order` and `payment` need unit tests for the error paths.
- No `Thread.sleep` in tests; inject a `Clock` for time.

Architecture decision records (ADRs) in docs/adr/ are also sent to the reviewer (the first 3,000 characters of each). An ADR is a short note of one decision: context, decision, consequences. Start with the one BoxOffice made in lab 1:

docs/adr/0001-schema-per-service.md
# ADR 0001 — One database schema per service

- Status: accepted
- Date: 2027-02-15

## Context
All BoxOffice services share one PostgreSQL instance (`db`, database `boxoffice`). Nothing in
PostgreSQL stops `order` from reading or updating `inventory.seats` directly, and a shortcut like
that would couple the two services' release cycles and bypass inventory's locking rules.

## Decision
Each service owns one schema (`catalog`, `inventory`, `orders`, `payment`, `notification`, `auth`)
and its Flyway migrations. A service reads and writes ONLY its own schema. Data owned by another
service is reached through that service's HTTP API or its events.

## Consequences
- A query across services becomes an API call or a read model built from events (slower, explicit).
- Each schema can move to its own database later without changing other services.
- Reviewers (human and AI) treat SQL that names another service's schema as a blocker.

Best practices in this lab

  • AI proposes, rules decide — .github/ai/review.py posts event: COMMENT, never an approval, and exits 0 when the model fails; why: Code review.
  • Privilege split by job — ai-fix.yaml runs the model with a read-only token and opens the draft PR from a job with no model; why: Agents in CI.
  • Generated tests prove their value — gen_tests.py keeps a test only if it passes twice and adds 5 pp of mutation score; why: Testing.
  • The verdict is code; the model only explains — canary_explain.py returns the exit code of the policy and discards an explanation that disagrees; why: Release & operate.
  • The AI tools have their own regression test — eval_review.py and ai-eval.yaml run the golden set when the prompt, conventions or model change; why: Security & governance.

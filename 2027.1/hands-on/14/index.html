a. Overview

In this lab

  • Replace lab 9's fake payment provider with a real one in a sandbox: Stripe's test mode, where no money moves.
  • Keep the contract order sees: payment still answers AUTHORIZED or DECLINED, behind a Psp interface with two implementations — the fake (still the default) and Stripe.
  • Receive Stripe's webhooks, check their signature, process each event once, and let a webhook record the charge whose answer was lost.
  • Reconcile your payments against the provider, the source of truth.
  • See how the same design takes Pix with Mercado Pago.

Lab 9 taught payment to survive a provider that is slow or down — against a WireMock that answers whatever we script. A real payment service provider (PSP) adds what a fake cannot: an account and keys, amounts in centavos, declined cards that are answers and not failures, and a second channel — the provider calls you back, later, maybe twice, to say what really happened. This lab plugs BoxOffice into Stripe's sandbox and handles all of it, without spending a cent.

The story so far

Chapter 10 of the story of the course, its second lab, which ties three threads together. Class 3 warned that between machines a message can be lost or duplicated: a retried "buy" can charge twice. Lab 9 answered with one idempotency key per order (order-<orderId>) against a fake provider, and showed the other face of a timeout: when lab 9's client gives up after 1 s and 3 attempts, the charge may still have happened — on a slow provider day the simulator below leaves 133 of 1,000 checkouts UNKNOWN. Class 12 adds that any endpoint the internet can reach must prove who is calling. This lab connects payment to a real provider's sandbox, turns the UNKNOWN into a known answer with signed webhooks and a reconciliation, and measures it: each checkout charged exactly once, and zero mismatches against the provider.

1. A Stripe sandbox

  1. Create an account at dashboard.stripe.com/register. You do not need to activate payments: a sandbox (Stripe's test environment) is available at once.
  2. In the Dashboard, open Developers → API keys of your sandbox and copy the secret key: it starts with sk_test_.
  3. Put it in .env, at the root of the repository — Compose reads it, and lab 0's .gitignore keeps it out of Git:
.env
PSP_PROVIDER=stripe
STRIPE_SECRET_KEY=sk_test_...

git check-ignore .env                  # prints ".env": it will never be committed
curl -s https://api.stripe.com/v1/balance -u "$(grep '^STRIPE_SECRET_KEY=' .env | cut -d= -f2-):" | jq '{object, livemode}'

You should see {"object": "balance", "livemode": false}. livemode: false is the sandbox: nothing you do here charges a real card.

A secret key is a password to your money

Never paste it in code, a commit, a screenshot or a chat. If it leaks, roll it in the Dashboard (Developers → API keys → Roll key). StripePsp refuses any key that does not start with sk_test_: in this course, a live key is a bug.

package boxoffice.payment;

import java.math.BigDecimal;
import java.net.http.HttpClient;
import java.time.Duration;
import java.util.UUID;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.boot.autoconfigure.condition.ConditionalOnProperty;
import org.springframework.http.MediaType;
import org.springframework.http.client.JdkClientHttpRequestFactory;
import org.springframework.stereotype.Component;
import org.springframework.util.LinkedMultiValueMap;
import org.springframework.util.MultiValueMap;
import org.springframework.web.client.RestClient;

/** The Stripe sandbox: one PaymentIntent per order, created and confirmed on the server. */
@Component
@ConditionalOnProperty(name = "boxoffice.psp.provider", havingValue = "stripe")
public class StripePsp implements Psp {

    /** The fields of a PaymentIntent this service reads. */
    record Intent(String id, String status) {
    }

    /** Stripe's error body: a declined card comes back as HTTP 402 with type card_error. */
    record ErrorBody(Error error) {
        record Error(String type, String code, String decline_code, String message, Intent payment_intent) {
        }
    }

    private final RestClient http;
    private final String currency;
    private final String defaultMethod;

    public StripePsp(RestClient.Builder builder,
                     @Value("${boxoffice.stripe.url}") String url,
                     @Value("${boxoffice.stripe.secret-key}") String secretKey,
                     @Value("${boxoffice.stripe.currency}") String currency,
                     @Value("${boxoffice.stripe.payment-method}") String defaultMethod,
                     @Value("${boxoffice.psp.connect-timeout}") Duration connectTimeout,
                     @Value("${boxoffice.psp.read-timeout}") Duration readTimeout) {
        if (!secretKey.startsWith("sk_test_")) {
            // a live key (sk_live_…) moves real money: this lab refuses to start with one
            throw new IllegalStateException("STRIPE_SECRET_KEY must be a test key (sk_test_…)");
        }
        // the JDK HttpClient keeps the body of an error answer (HttpURLConnection may drop it)
        JdkClientHttpRequestFactory factory = new JdkClientHttpRequestFactory(
                HttpClient.newBuilder().connectTimeout(connectTimeout).build());
        factory.setReadTimeout(readTimeout);
        this.http = builder.baseUrl(url)
                .defaultHeader("Authorization", "Bearer " + secretKey)
                .requestFactory(factory)
                .build();
        this.currency = currency;
        this.defaultMethod = defaultMethod;
    }

    @Override
    public Charge charge(String idempotencyKey, BigDecimal amount, UUID orderId, String paymentMethod) {
        MultiValueMap<String, String> form = new LinkedMultiValueMap<>();
        form.add("amount", String.valueOf(amount.movePointRight(2).longValueExact())); // centavos
        form.add("currency", currency);
        form.add("payment_method", paymentMethod != null ? paymentMethod : defaultMethod);
        form.add("confirm", "true");                                   // charge now, on the server
        form.add("automatic_payment_methods[enabled]", "true");
        form.add("automatic_payment_methods[allow_redirects]", "never"); // no browser to redirect
        form.add("metadata[order_id]", orderId.toString());
        form.add("metadata[idempotency_key]", idempotencyKey);         // lets a webhook find the payment
        return http.post()
                .uri("/v1/payment_intents")
                .header("Idempotency-Key", idempotencyKey)             // Stripe charges once per key
                .contentType(MediaType.APPLICATION_FORM_URLENCODED)
                .body(form)
                .exchange((request, response) -> {
                    if (response.getStatusCode().is2xxSuccessful()) {
                        Intent intent = response.bodyTo(Intent.class);
                        return new Charge(intent.id(), "succeeded".equals(intent.status()));
                    }
                    ErrorBody body = response.bodyTo(ErrorBody.class);
                    if (response.getStatusCode().value() == 402 && body != null && body.error().payment_intent() != null) {
                        return new Charge(body.error().payment_intent().id(), false); // declined: an answer, not a failure
                    }
                    String message = body != null ? body.error().message() : response.getStatusText();
                    throw new IllegalStateException("Stripe answered " + response.getStatusCode().value() + ": " + message);
                });
    }

    /** The provider's view of one PaymentIntent: the source of truth for reconciliation. */
    public Intent retrieve(String intentId) {
        return http.get().uri("/v1/payment_intents/{id}", intentId).retrieve().body(Intent.class);
    }
}

package boxoffice.payment;

import java.math.BigDecimal;
import java.time.Duration;
import java.util.UUID;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.boot.autoconfigure.condition.ConditionalOnProperty;
import org.springframework.http.client.SimpleClientHttpRequestFactory;
import org.springframework.stereotype.Component;
import org.springframework.web.client.RestClient;

/** Lab 9's fake provider (WireMock behind Toxiproxy): still the default, so the chaos experiments keep working. */
@Component
@ConditionalOnProperty(name = "boxoffice.psp.provider", havingValue = "fake", matchIfMissing = true)
public class PspClient implements Psp {

    record ChargeBody(BigDecimal amount, String currency, String reference) {
    }

    record ChargeOut(String id, String status) {
    }

    private final RestClient http;

    public PspClient(RestClient.Builder builder,
                     @Value("${boxoffice.psp.url}") String url,
                     @Value("${boxoffice.psp.connect-timeout}") Duration connectTimeout,
                     @Value("${boxoffice.psp.read-timeout}") Duration readTimeout) {
        SimpleClientHttpRequestFactory factory = new SimpleClientHttpRequestFactory();
        factory.setConnectTimeout(connectTimeout); // time to open the TCP connection
        factory.setReadTimeout(readTimeout);       // max silence while waiting for the response
        this.http = builder.baseUrl(url).requestFactory(factory).build();
    }

    /** The provider deduplicates by Idempotency-Key, like real PSPs do. */
    @Override
    public Charge charge(String idempotencyKey, BigDecimal amount, UUID orderId, String paymentMethod) {
        ChargeOut out = http.post()
                .uri("/v1/charges")
                .header("Idempotency-Key", idempotencyKey)
                .body(new ChargeBody(amount, "BRL", "order-" + orderId))
                .retrieve()
                .body(ChargeOut.class);
        return new Charge(out.id(), "approved".equals(out.status()));
    }
}

What StripePsp does, and why:

  • One PaymentIntent per order, confirmed on the server. confirm=true charges at once with the test payment method (pm_card_visa by default — in a real checkout, Stripe.js in the browser turns the card into such an id, so card numbers never touch BoxOffice). allow_redirects=never: there is no browser to send to a bank page.
  • Amounts in centavos. R$ 350.00 is amount=35000; movePointRight(2).longValueExact() fails loudly on a fraction of a centavo instead of rounding money.
  • The same Idempotency-Key as payment's own table (order-<orderId> from order). Stripe stores the result of the first request with a key and replays it for every retry with the same key, so a retry after a crash between "Stripe charged" and "we saved it" cannot charge twice.
  • A declined card is an answer. Stripe returns HTTP 402 with type: card_error and the PaymentIntent; payment records DECLINED. Anything else (401, 5xx, a timeout) is an exception: lab 9's retry, breaker and fallback in order handle it.
  • Metadata order_id and idempotency_key travel with the PaymentIntent: the webhook of step 4 uses them to find — or create — the payment.

import org.springframework.beans.factory.annotation.Value;
import org.springframework.boot.autoconfigure.condition.ConditionalOnProperty;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.PostMapping;

/** Stripe tells us what happened, later and maybe twice: the webhook is the source of truth. */
@RestController
@ConditionalOnProperty(name = "boxoffice.psp.provider", havingValue = "stripe")
public class StripeWebhookController {

    private static final Logger log = LoggerFactory.getLogger(StripeWebhookController.class);

    record Event(String id, String type, Data data) {
        record Data(Intent object) {
        }

        record Intent(String id, String status, long amount, Map<String, String> metadata) {
        }
    }

    private final PaymentService payments;
    private final ObjectMapper json;
    private final String secret;
    private final Duration tolerance;
    private final Clock clock = Clock.systemUTC();

    public StripeWebhookController(PaymentService payments, ObjectMapper json,
                                   @Value("${boxoffice.stripe.webhook-secret}") String secret,
                                   @Value("${boxoffice.stripe.tolerance}") Duration tolerance) {
        this.payments = payments;
        this.json = json;
        this.secret = secret;
        this.tolerance = tolerance;
    }

    /** The raw body, as a String: the signature is computed over the exact bytes Stripe sent. */
    @PostMapping("/webhooks/stripe")
    public ResponseEntity<String> receive(@RequestBody String body,
                                          @RequestHeader(value = "Stripe-Signature", required = false) String signature) {
        if (!StripeSignature.valid(body, signature, secret, tolerance, clock)) {
            log.warn("webhook rejected: bad or missing Stripe-Signature");
            return ResponseEntity.badRequest().body("bad signature");
        }
        Event event = json.readValue(body, Event.class);
        String status = switch (event.type()) {
            case "payment_intent.succeeded" -> "AUTHORIZED";
            case "payment_intent.payment_failed" -> "DECLINED";
            default -> null; // other events: acknowledged, ignored
        };
        if (status == null) {
            return ResponseEntity.ok("ignored");
        }
        Event.Intent intent = event.data().object();
        boolean applied = payments.applyWebhook(event.id(), event.type(), intent.id(), status, intent.amount(), intent.metadata());
        log.info("webhook {} {} {} → {}", event.id(), event.type(), intent.id(), applied ? status : "duplicate, skipped");
        return ResponseEntity.ok(applied ? "applied" : "duplicate"); // 2xx quickly, or Stripe retries
    }
}

package boxoffice.payment;

import java.nio.charset.StandardCharsets;
import java.security.MessageDigest;
import java.time.Clock;
import java.time.Duration;
import java.util.HexFormat;
import javax.crypto.Mac;
import javax.crypto.spec.SecretKeySpec;

/**
 * Checks the Stripe-Signature header of a webhook: t=<unix time>,v1=<hex HMAC-SHA256 of "t.body">.
 * Without it, anyone who finds the URL can post "payment succeeded".
 */
public final class StripeSignature {

    private StripeSignature() {
    }

    public static boolean valid(String body, String header, String secret, Duration tolerance, Clock clock) {
        if (header == null || secret == null || secret.isBlank()) {
            return false;
        }
        String timestamp = null;
        String expected = null;
        for (String part : header.split(",")) {
            String[] kv = part.split("=", 2);
            if (kv.length == 2 && kv[0].equals("t")) {
                timestamp = kv[1];
            } else if (kv.length == 2 && kv[0].equals("v1") && expected == null) {
                expected = kv[1];
            }
        }
        if (timestamp == null || expected == null) {
            return false;
        }
        long age = clock.instant().getEpochSecond() - Long.parseLong(timestamp);
        if (Math.abs(age) > tolerance.toSeconds()) {
            return false; // an old, replayed request: even with a correct signature
        }
        String computed = hmacSha256Hex(secret, timestamp + "." + body);
        // constant-time comparison: do not leak, byte by byte, how much of the signature matched
        return MessageDigest.isEqual(computed.getBytes(StandardCharsets.UTF_8), expected.getBytes(StandardCharsets.UTF_8));
    }

    static String hmacSha256Hex(String secret, String payload) {
        try {
            Mac mac = Mac.getInstance("HmacSHA256");
            mac.init(new SecretKeySpec(secret.getBytes(StandardCharsets.UTF_8), "HmacSHA256"));
            return HexFormat.of().formatHex(mac.doFinal(payload.getBytes(StandardCharsets.UTF_8)));
        } catch (Exception e) {
            throw new IllegalStateException(e);
        }
    }
}

package boxoffice.payment;

import java.math.BigDecimal;
import java.util.List;
import java.util.Map;
import java.util.Optional;
import java.util.UUID;
import org.springframework.jdbc.core.simple.JdbcClient;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

@Service
public class PaymentService {

    public record Result(PaymentOut payment, boolean created) {
    }

    private final JdbcClient jdbc;
    private final Psp psp;

    public PaymentService(JdbcClient jdbc, Psp psp) {
        this.jdbc = jdbc;
        this.psp = psp;
    }

    public Result charge(String idempotencyKey, ChargeRequest req) {
        Optional<PaymentOut> done = find(idempotencyKey);
        if (done.isPresent()) {
            return new Result(done.get(), false); // a retry: answer, do not charge again
        }
        // remote call OUTSIDE any database transaction: never hold a connection while waiting
        Psp.Charge charge = psp.charge(idempotencyKey, req.amount(), req.orderId(), req.paymentMethod());
        String status = charge.approved() ? "AUTHORIZED" : "DECLINED";
        jdbc.sql("""
                INSERT INTO payments (id, idempotency_key, order_id, amount, status, provider_ref)
                VALUES (?, ?, ?, ?, ?, ?)
                ON CONFLICT DO NOTHING
                """)
                .params(UUID.randomUUID(), idempotencyKey, req.orderId(), req.amount(), status, charge.id())
                .update();
        return new Result(find(idempotencyKey).orElseThrow(), true);
    }

    /**
     * Applies a webhook once per event id. Updates the payment of that PaymentIntent, or creates it when
     * the charge went through but its answer never arrived (the caller timed out): the gap the webhook heals.
     * Returns false for a duplicate delivery.
     */
    @Transactional
    public boolean applyWebhook(String eventId, String type, String intentId, String status,
                                long amountInCents, Map<String, String> metadata) {
        int fresh = jdbc.sql("INSERT INTO stripe_events (id, type) VALUES (?, ?) ON CONFLICT DO NOTHING")
                .params(eventId, type).update();
        if (fresh == 0) {
            return false; // already processed: Stripe delivers at least once
        }
        int updated = jdbc.sql("UPDATE payments SET status = ? WHERE provider_ref = ?")
                .params(status, intentId).update();
        if (updated == 0 && metadata != null && metadata.containsKey("idempotency_key")) {
            jdbc.sql("""
                    INSERT INTO payments (id, idempotency_key, order_id, amount, status, provider_ref)
                    VALUES (?, ?, ?, ?, ?, ?)
                    ON CONFLICT DO NOTHING
                    """)
                    .params(UUID.randomUUID(), metadata.get("idempotency_key"), UUID.fromString(metadata.get("order_id")),
                            BigDecimal.valueOf(amountInCents).movePointLeft(2), status, intentId)
                    .update();
        }
        return true;
    }

    /** The payments of the last hours, with their provider reference: what reconciliation checks. */
    public List<PaymentOut> since(java.time.Duration window) {
        return jdbc.sql("""
                SELECT id, order_id, amount, status, provider_ref, created_at
                FROM payments WHERE created_at > now() - make_interval(secs => ?)
                ORDER BY created_at
                """)
                .param(window.toSeconds())
                .query(PaymentOut.class)
                .list();
    }

    private Optional<PaymentOut> find(String idempotencyKey) {
        return jdbc.sql("""
                SELECT id, order_id, amount, status, provider_ref, created_at
                FROM payments WHERE idempotency_key = ?
                """)
                .param(idempotencyKey)
                .query(PaymentOut.class)
                .optional();
    }
}

  • The signature. Stripe-Signature: t=<unix time>,v1=<hex> where v1 is the HMAC-SHA256 (a hash-based message authentication code: a SHA-256 hash keyed with the endpoint's secret) of <t>.<raw body>. The controller reads the body as a String — parsing first and serializing again would change the bytes — compares in constant time and rejects a timestamp older than 5 minutes, so a captured request cannot be replayed later.
  • Once per event. stripe_events has the event id as primary key; INSERT … ON CONFLICT DO NOTHING returns 0 for a repeat, and the repeat is acknowledged and skipped.
  • The webhook heals. If no payment has that PaymentIntent — the charge went through but its answer never reached the database — the metadata recreates it, with the same idempotency key. The next pay of that order finds it.

package boxoffice.payment;

import java.time.Duration;
import java.util.ArrayList;
import java.util.List;
import org.springframework.boot.autoconfigure.condition.ConditionalOnProperty;
import org.springframework.web.client.HttpClientErrorException;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

/** Compares our payments with Stripe's PaymentIntents: what the provider says wins. */
@RestController
@ConditionalOnProperty(name = "boxoffice.psp.provider", havingValue = "stripe")
public class Reconciliation {

    record Mismatch(String providerRef, String ours, String stripe) {
    }

    record Report(int checked, List<Mismatch> mismatches) {
    }

    private final PaymentService payments;
    private final StripePsp stripe;

    public Reconciliation(PaymentService payments, StripePsp stripe) {
        this.payments = payments;
        this.stripe = stripe;
    }

    @GetMapping("/payments/reconcile")
    public Report reconcile(@RequestParam(defaultValue = "PT1H") Duration window) {
        List<PaymentOut> ours = payments.since(window);
        List<Mismatch> mismatches = new ArrayList<>();
        for (PaymentOut p : ours) {
            if (p.providerRef() == null || !p.providerRef().startsWith("pi_")) {
                continue; // not a Stripe payment (lab 9's fake provider)
            }
            String theirs;
            try {
                theirs = stripe.retrieve(p.providerRef()).status();
            } catch (HttpClientErrorException.NotFound e) {
                theirs = "missing"; // a payment Stripe never made: the worst mismatch
            }
            String expected = switch (theirs) {
                case "succeeded" -> "AUTHORIZED";
                case "requires_payment_method", "canceled" -> "DECLINED";
                default -> null; // processing, requires_action, missing…: always worth a look
            };
            if (!p.status().equals(expected)) {
                mismatches.add(new Mismatch(p.providerRef(), p.status(), theirs));
            }
        }
        return new Report(ours.size(), mismatches);
    }
}

Costs and limits of the sandbox

The sandbox has rate limits lower than live mode and keeps test data until you delete it (Developers → … → Delete all test data). GET /payments/reconcile makes one Stripe call per payment: fine for a lab, a job with pagination (GET /v1/payment_intents?created[gte]=…) for real volumes.

7. Pix with Mercado Pago

The Psp interface is the seam for any provider. Mercado Pago is the common choice in Brazil for Pix, and Pix changes one thing in the flow: the answer to "charge" is not "paid" — it is a QR code. The fan pays later, in the bank's app, and only the webhook says the money arrived. What is a safety net with Stripe's cards becomes the main path.

Best practices in this lab

  • Keep the provider behind an interface — Psp with PspClient and StripePsp; order never learns which one charged (Compute — external integrations).
  • One idempotency key per order, end to end — order-<orderId> from order, the unique column of payments and Stripe's Idempotency-Key are the same value, so no retry anywhere charges twice (Distributed Systems).
  • Treat a decline as an answer, not a failure — StripePsp maps the 402 to DECLINED; only real failures reach lab 9's retry and breaker (Reliability patterns).
  • Verify every webhook, process each event once — StripeSignature (HMAC, constant time, 5-minute tolerance) and the stripe_events table (Network & Security).
  • Reconcile against the source of truth — Reconciliation finds what webhooks missed; money needs a second check, not trust (Observability).
  • Secrets from the environment, test keys only — .env ignored by Git, sk_test_ enforced at startup.

What breaks next

Every checkout is now charged once and every charge is known — but knowing is not fixing. The reconciliation's mismatch is a fan who paid for an order BoxOffice cancelled: that needs a refund (POST /v1/refunds) or a late confirmation, decided by a job, not by hand. Cards that ask for 3-D Secure need the fan's browser (Stripe.js), which means a front end and a requires_action state the server alone cannot finish. Pix makes "pending" the normal case, so order must learn a third state. And real money means live keys, a verified business and the card-data rules of the Payment Card Industry Data Security Standard (PCI DSS) — kept small precisely because card numbers never touch BoxOffice. Whether all of this still holds at 10:00, with 2 million fans, is the question of class 15 — Performance Engineering and of your project.

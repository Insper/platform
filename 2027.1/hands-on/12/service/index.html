1. The Service and the LLM Gateway

This step creates the assistant service — Python 3.12 + FastAPI, managed with uv — and its LLM gateway: the one module that knows which models exist, which one answers by default, what to do when a provider fails, and how much each answer costs. All commands run from the root of your boxoffice repository unless a cd says otherwise.

Infrastructure: a local LLM and a vector-capable PostgreSQL

Container Image Port Role
ollama ollama/ollama:0.40.6 11434 runs the local models: qwen2.5:1.5b (chat, with tool calling) and nomic-embed-text (embeddings, 768 dimensions)
ollama-init ollama/ollama:0.40.6 — one-shot: downloads both models (≈ 1.3 GB, once)
db and db-replica pgvector/pgvector:0.8.7-pg17-trixie 5432 / 5433 the same PostgreSQL 17, now with the vector extension available
assistant services/assistant 8088 the FastAPI service of this lab

The new part of docker-compose.yaml:

docker-compose.yaml (excerpt)
  ollama:
    image: ollama/ollama:0.40.6
    ports:
      - "11434:11434"
    volumes:
      - ollama-models:/root/.ollama      # models survive restarts (about 1.3 GB)
    healthcheck:                         # ollama-init must wait for the server, not just the container
      test: ["CMD", "ollama", "list"]
      interval: 5s
      timeout: 5s
      retries: 12

  # one-shot: download the chat model and the embedding model, then exit
  ollama-init:
    image: ollama/ollama:0.40.6
    environment:
      OLLAMA_HOST: ollama:11434
    entrypoint: ["/bin/sh", "-c"]
    command:
      - |
        ollama pull ${LOCAL_MODEL_TAG:-qwen2.5:1.5b} && ollama pull nomic-embed-text
    depends_on:
      ollama:
        condition: service_healthy
    restart: "no"

Where should the model run? (read before pulling)

A language model is a lot of arithmetic; where it runs decides your latency.

Docker on macOS has no GPU access: in a container the model runs on the CPU and a short answer can take a minute. Run Ollama natively instead (it uses the GPU through Metal) and point the assistant at it:

brew install ollama && ollama serve &          # or the app from ollama.com
ollama pull qwen2.5:1.5b && ollama pull nomic-embed-text
export OLLAMA_URL=http://host.docker.internal:11434

and skip the ollama and ollama-init containers below.

Install the NVIDIA Container Toolkit and add to the ollama service: deploy: { resources: { reservations: { devices: [{ driver: nvidia, count: all, capabilities: [gpu] }] } } }.

Use the containers as they are. It works, slowly: in a test run on a busy 8-core laptop the first token took tens of seconds. Prefer short questions, and compare with the optional Claude route of this page.

Start the infrastructure (the db image changes, so db restarts once):

docker compose up -d db db-replica ollama ollama-initdocker compose wait ollama-initcontainer "c8d93485…" exited with status code 0docker compose exec ollama ollama listNAME ID SIZE MODIFIED

docker compose wait blocks until the one-shot ollama-init has downloaded both models (a minute or two the first time) and prints its exit code: 0. (docker compose logs -f ollama-init would not return if the container has already exited.) You should see both models in the list (ollama list on your machine if Ollama runs natively). With native Ollama (macOS), start only docker compose up -d db db-replica: an ollama container would fail with port is already allocated on 11434, which the native server already uses.

uv (from Astral) creates the virtual environment, resolves the dependencies and writes a lock file with the exact version and hash of every package, so that your laptop, CI and the container install the same bytes. The project was created with these commands (you can run them yourself in an empty services/assistant/, or download the files below):

"""All settings come from environment variables (the same names in Compose and in Kubernetes)."""
import os
from dataclasses import dataclass


@dataclass(frozen=True)
class Settings:
    db_dsn: str
    ollama_url: str
    local_model: str        # LiteLLM model name of the local chat model
    embed_model: str        # LiteLLM model name of the embedding model
    embed_dim: int          # dimension of the embedding vectors (nomic-embed-text: 768)
    claude_model: str | None  # set only when ANTHROPIC_API_KEY exists
    default_route: str      # "local" or "claude"
    catalog_url: str
    order_url: str
    max_steps: int          # agent loop: maximum LLM calls per question
    max_input_chars: int
    retrieve_k: int


def load() -> Settings:
    env = os.environ.get
    has_key = bool(env("ANTHROPIC_API_KEY"))
    return Settings(
        db_dsn=(
            f"host={env('DB_HOST', 'db')} port={env('DB_PORT', '5432')} "
            f"dbname={env('DB_NAME', 'boxoffice')} user={env('DB_USER', 'boxoffice')} "
            f"password={env('DB_PASSWORD', 'boxoffice')}"
        ),
        ollama_url=env("OLLAMA_URL", "http://ollama:11434"),
        local_model=env("LOCAL_MODEL", "ollama_chat/qwen2.5:1.5b"),
        embed_model=env("EMBED_MODEL", "ollama/nomic-embed-text"),
        embed_dim=int(env("EMBED_DIM", "768")),
        claude_model=env("CLAUDE_MODEL", "anthropic/claude-opus-5-5") if has_key else None,
        default_route=env("ASSISTANT_ROUTE", "claude" if has_key else "local"),

services/assistant/app/llm.py
"""The LLM gateway: one place that knows models, routes, fallbacks, timeouts and costs."""
import litellm
from litellm import Router

from .config import settings

litellm.drop_params = True  # drop parameters a provider does not support instead of failing

model_list = [{
    "model_name": "local",
    "litellm_params": {"model": settings.local_model, "api_base": settings.ollama_url},
}]
fallbacks = []
if settings.claude_model:  # optional: only when ANTHROPIC_API_KEY is set
    model_list.append({"model_name": "claude", "litellm_params": {"model": settings.claude_model}})
    fallbacks = [{"claude": ["local"]}]  # provider down or out of quota: answer with the local model

router = Router(model_list=model_list, fallbacks=fallbacks, num_retries=1, timeout=120)


def real_model(route: str) -> str:
    """The provider model behind a route name (for metrics and costs)."""
    return settings.claude_model if route == "claude" and settings.claude_model else settings.local_model


async def embed(texts: list[str]) -> list[list[float]]:
    response = await litellm.aembedding(model=settings.embed_model, input=texts, api_base=settings.ollama_url)
    return [item["embedding"] for item in response.data]

LiteLLM gives every provider the same OpenAI-style interface, and its Router is the gateway of the LLM gateway class:

Concern Here
Routing two routes: local (Ollama) always, claude only when ANTHROPIC_API_KEY is set; ASSISTANT_ROUTE or the request's route field chooses
Fallback claude → local when the provider fails (outage, rate limit, no credit)
Timeouts and retries 120 s per call, 1 retry — an LLM call is the slowest dependency BoxOffice has
Cost app/metrics.py (step 4) multiplies the tokens of each answer by the provider's price

Why an in-process SDK and not the LiteLLM proxy?

LiteLLM also runs as a separate proxy (an OpenAI-compatible HTTP server with keys, budgets and a UI) shared by many services. One service does not need it: the in-process Router has the same routing logic without another container. With several AI services, the proxy becomes the shared gateway — the same move as from per-service resilience (lab 9) to a service mesh.

The optional Claude route (costs money)

The lab works end to end with the local model. To compare with a frontier model, create an API key at console.anthropic.com (pay-as-you-go: you are charged per token — the default anthropic/claude-opus-5-5 costs US$ 4 per million input tokens and US$ 20 per million output tokens; one question of this lab uses about 1 000 input and 100 output tokens, ≈ US$ 0.006) and export it before starting the assistant:

export ANTHROPIC_API_KEY=sk-ant-...       # never commit it; docker-compose.yaml reads it from the shell

With the key, the default route becomes claude; send "route": "local" in a request to compare. Without it, nothing calls the paid API.

Route claude without meaning to?

Then ANTHROPIC_API_KEY is already set in your shell (other tools use the same variable), and every question goes to the paid API. unset ANTHROPIC_API_KEY and run docker compose up -d --wait assistant again: the health check must show "route":"local".

Ferramentas

As ferramentas do ofício, agrupadas por função. Para cada uma: o que é em uma linha, quando recorrer a ela, o laboratório em que a usamos neste curso e o site oficial. A pilha do curso é pequena de propósito: Docker Compose para rodar tudo localmente, k6 para testes de carga, OpenTelemetry + grafana/otel-lgtm para observar, Toxiproxy para injetar falhas, kind ou minikube para Kubernetes, GitHub Actions e Argo CD para entregar, e LiteLLM + Ollama + pgvector para o serviço de IA. As alternativas estão listadas para que você as reconheça em vagas de emprego e em blogs de engenharia.

Sobre os links

Os links levam ao site oficial ou ao repositório oficial de cada projeto. As ferramentas mudam rápido: confira a documentação atual antes de copiar um comando de um post de blog, e fixe as versões no seu docker-compose.yaml e nos arquivos de CI.

Teste de carga

Ferramenta O que é Use quando No curso Site
k6 Ferramenta de teste de carga com scripts em JavaScript e thresholds que reprovam uma execução (ótima para CI) Você quer scripts legíveis, perfis smoke/load/stress/spike/soak e critérios de aprovação Hands-on 2, toda etapa "Meça", gate de CI no Hands-on 11 k6.io
Gatling Teste de carga com cenários em Java, Kotlin ou Scala e relatórios HTML detalhados O time vive na JVM e quer cenários escritos como código Alternativa ao k6 gatling.io
Locust Teste de carga com o comportamento dos usuários escrito em Python Você prefere Python, ou precisa de protocolos customizados Alternativa ao k6 locust.io
Apache JMeter Veterana ferramenta de teste de carga com interface gráfica, muitos protocolos Você herda planos JMeter existentes ou precisa dos plugins de protocolo Reconheça jmeter.apache.org
wrk2 Pequena ferramenta de benchmark HTTP com taxa de requisições constante, corrigida para coordinated omission Você precisa de uma distribuição de latência rápida e honesta a uma taxa fixa Aula 15 (coordinated omission) github.com/giltene/wrk2
vegeta Ferramenta de carga HTTP com taxa de ataque constante, usável como CLI ou biblioteca Go Testes de modelo aberto (taxa fixa) pela linha de comando Alternativa para testes rápidos github.com/tsenart/vegeta
oha / hey Geradores mínimos de carga HTTP pela linha de comando Uma verificação de dez segundos, não uma campanha de testes Verificações rápidas oha · hey

Carga aberta vs fechada

A maioria das ferramentas usa por padrão um modelo fechado (N usuários virtuais, cada um esperando sua resposta antes de enviar a próxima). O tráfego real da internet se parece mais com um modelo aberto (as requisições chegam a uma taxa, quer o servidor acompanhe, quer não). Os executores constant-arrival-rate e ramping-arrival-rate do k6, o wrk2 e o vegeta geram carga aberta; use-os quando quiser ver as filas se formarem. Veja a Aula 15 · Testes de carga.

Aprenda o trabalho, não só a ferramenta

Entrevistadores raramente se importam se você usou k6 ou Gatling. Importa se você sabe o que medir (percentis a uma taxa-alvo, o joelho, o gargalo) e por quê. Aprenda bem uma ferramenta por trabalho e saiba dizer o que as alternativas fazem de diferente.

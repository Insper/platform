1. Pagamento, Provedor e Toxiproxy

O BoxOffice não movimenta dinheiro sozinho: o serviço payment é um adaptador para um provedor externo de serviços de pagamento (PSP, payment service provider). Isso faz dele a dependência mais perigosa do checkout — lento num dia movimentado, fora do seu controle, e o lugar onde um retry pode cobrar um fã duas vezes. Este passo constrói as três peças que o resto do lab quebra de propósito:

Contêiner Imagem / build Porta Papel
psp wiremock/wiremock:3.13.2 8080 (interna) um provedor externo falso: POST /v1/charges responde approved
payment services/payment (Spring Boot) 8085 adaptador: POST /payments idempotente, chama o PSP com timeouts
toxiproxy ghcr.io/shopify/toxiproxy:2.13.0 8474 (API) proxy TCP na frente do payment e do psp; injeta latência, resets, quedas 
flowchart LR
    order[order] -->|"PAYMENT_URL = toxiproxy:18085"| tp1["toxiproxy proxy: payment"]
    tp1 --> payment[payment :8085]
    payment -->|"PSP_URL = toxiproxy:18095"| tp2["toxiproxy proxy: psp"]
    tp2 --> psp["psp (WireMock)"]
    payment --> db[(db: schema payment)]
    you[você / game day] -->|"curl :8474 adiciona toxic"| tp1

Toda chamada atravessa um proxy do Toxiproxy, então você consegue deixar qualquer salto lento ou quebrado sem tocar no código: o Toxiproxy trabalha no nível TCP, abaixo do HTTP, exatamente onde as redes reais falham.

O cliente do provedor define os dois timeouts explicitamente. Sem eles, um cliente HTTP Java espera uma resposta para sempre — a causa raiz da maioria das falhas em cascata.

services/payment/src/main/java/boxoffice/payment/PspClient.java
package boxoffice.payment;

import java.math.BigDecimal;
import java.time.Duration;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.http.client.SimpleClientHttpRequestFactory;
import org.springframework.stereotype.Component;
import org.springframework.web.client.RestClient;

@Component
public class PspClient {

    record ChargeBody(BigDecimal amount, String currency, String reference) {
    }

    record Charge(String id, String status) {
    }

    private final RestClient http;

    public PspClient(RestClient.Builder builder,
                     @Value("${boxoffice.psp.url}") String url,
                     @Value("${boxoffice.psp.connect-timeout}") Duration connectTimeout,
                     @Value("${boxoffice.psp.read-timeout}") Duration readTimeout) {
        SimpleClientHttpRequestFactory factory = new SimpleClientHttpRequestFactory();
        factory.setConnectTimeout(connectTimeout); // time to open the TCP connection
        factory.setReadTimeout(readTimeout);       // max silence while waiting for the response
        this.http = builder.baseUrl(url).requestFactory(factory).build();
    }

    /** The provider deduplicates by Idempotency-Key, like real PSPs do. */
    public Charge charge(String idempotencyKey, BigDecimal amount, String reference) {
        return http.post()
                .uri("/v1/charges")
                .header("Idempotency-Key", idempotencyKey)
                .body(new ChargeBody(amount, "BRL", reference))
                .retrieve()
                .body(Charge.class);
    }
}
services/payment/src/main/java/boxoffice/payment/PaymentService.java
package boxoffice.payment;

import java.util.Optional;
import java.util.UUID;
import org.springframework.jdbc.core.simple.JdbcClient;
import org.springframework.stereotype.Service;

@Service
public class PaymentService {

    public record Result(PaymentOut payment, boolean created) {
    }

    private final JdbcClient jdbc;
    private final PspClient psp;

    public PaymentService(JdbcClient jdbc, PspClient psp) {
        this.jdbc = jdbc;
        this.psp = psp;
    }

    public Result charge(String idempotencyKey, ChargeRequest req) {
        Optional<PaymentOut> done = find(idempotencyKey);
        if (done.isPresent()) {
            return new Result(done.get(), false); // a retry: answer, do not charge again
        }
        // remote call OUTSIDE any database transaction: never hold a connection while waiting
        PspClient.Charge charge = psp.charge(idempotencyKey, req.amount(), "order-" + req.orderId());
        String status = "approved".equals(charge.status()) ? "AUTHORIZED" : "DECLINED";
        jdbc.sql("""
                INSERT INTO payments (id, idempotency_key, order_id, amount, status, provider_ref)
                VALUES (?, ?, ?, ?, ?, ?)
                ON CONFLICT (idempotency_key) DO NOTHING
                """)
                .params(UUID.randomUUID(), idempotencyKey, req.orderId(), req.amount(), status, charge.id())
                .update();
        return new Result(find(idempotencyKey).orElseThrow(), true);
    }

    private Optional<PaymentOut> find(String idempotencyKey) {
        return jdbc.sql("""
                SELECT id, order_id, amount, status, provider_ref, created_at
                FROM payments WHERE idempotency_key = ?
                """)
                .param(idempotencyKey)
                .query(PaymentOut.class)
                .optional();
    }
}
services/payment/src/main/java/boxoffice/payment/PaymentController.java
package boxoffice.payment;

import jakarta.validation.Valid;
import java.net.URI;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestHeader;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("/payments")
public class PaymentController {

    private final PaymentService payments;

    public PaymentController(PaymentService payments) {
        this.payments = payments;
    }

    @PostMapping
    public ResponseEntity<PaymentOut> charge(@RequestHeader("Idempotency-Key") String idempotencyKey,
                                             @Valid @RequestBody ChargeRequest req) {
        PaymentService.Result r = payments.charge(idempotencyKey, req);
        return r.created()
                ? ResponseEntity.created(URI.create("/payments/" + r.payment().id())).body(r.payment())
                : ResponseEntity.ok(r.payment());
    }
}

Idempotência de ponta a ponta

A mesma chave viaja order → payment → PSP: o order envia Idempotency-Key: order-<id>, o payment a guarda com uma restrição UNIQUE e a repassa ao provedor. Um retry em qualquer camada — o Resilience4j no order, um timeout no gateway, um fã clicando duas vezes — encontra a chave e recebe de volta o primeiro resultado. Retries só são seguros sobre idempotência; este é o estudo de caso do sistema de pagamentos em miniatura.

O seu primeiro toxic

Adicione 3 segundos de latência a toda resposta do proxy psp, cronometre um pagamento e remova o toxic:

curl -s -X POST localhost:8474/proxies/psp/toxics \
  -d '{"name":"slow","type":"latency","stream":"downstream","attributes":{"latency":3000}}'
time curl -s -X POST localhost:8085/payments -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: test-2' -d '{"orderId":"5b0c2f9e-7d0a-4f43-9a55-1c1c2c8f8e10","amount":350.00}'
curl -s -X DELETE localhost:8474/proxies/psp/toxics/slow

Você deve ver {"…","status":500,"error":"Internal Server Error","path":"/payments"} depois de real 0m2.2s: o timeout de leitura do PspClient (2 s) disparou antes de a resposta de 3 s chegar. Sem ele, a thread teria esperado os 3 s inteiros — ou para sempre.

Toxic Atributos Simula
latency latency, jitter (ms) uma dependência lenta, uma rede congestionada
timeout timeout (ms; 0 = nunca fecha) um buraco negro: os pacotes entram, nada volta
reset_peer timeout (ms) conexão resetada pelo outro lado (um crash, um load balancer matando conexões)
bandwidth rate (KB/s) um cano estreito
limit_data bytes uma conexão cortada no meio de uma resposta
(proxy desativado) POST /proxies/<name> com {"enabled": false} a dependência está fora do ar: conexão recusada

Cada toxic também aceita uma toxicity entre 0 e 1: a probabilidade de que ele se aplique a uma nova conexão — perfeito para "30% das chamadas falham".

1. Instrumente Tudo

Neste passo cada serviço Java passa a enviar traces, métricas e logs para um único contêiner, o otel-lgtm, sem nenhuma mudança no código de negócio. Depois você corrige o único lugar onde a instrumentação automática não enxerga a requisição: o salto pelo outbox do lab 7. Todos os comandos rodam na raiz do seu repositório boxoffice.

O backend: otel-lgtm

O grafana/otel-lgtm reúne um backend de observabilidade inteiro em uma imagem, para desenvolvimento e ensino: um OpenTelemetry Collector recebe OTLP (o OpenTelemetry Protocol) e encaminha cada sinal para o Prometheus (métricas), o Tempo (traces) e o Loki (logs), com o Grafana por cima, já ligado de modo que um exemplar de métrica abre o seu trace e um trace abre os seus logs. Em produção esses são sistemas separados e replicados (ou um serviço gerenciado); o protocolo que seus serviços falam — o OTLP — continua o mesmo.

docker-compose.yaml (excerpt)
  otel-lgtm:
    image: grafana/otel-lgtm:0.37.0
    ports:
      - "3000:3000"   # Grafana (no login)
      - "4317:4317"   # OTLP gRPC
      - "4318:4318"   # OTLP HTTP
    volumes:
      - ./infra/grafana/dashboards.yaml:/otel-lgtm/grafana/conf/provisioning/dashboards/boxoffice.yaml:ro
      - ./infra/grafana/dashboards:/otel-lgtm/boxoffice-dashboards:ro
      - ./infra/grafana/alerting:/otel-lgtm/grafana/conf/provisioning/alerting:ro

Os três volumes carregam o seu dashboard e as suas regras de alerta na inicialização; os arquivos são criados no passo 2 e no passo 3.

O agente: um jar, nenhum código

O agente Java do OpenTelemetry é conectado à JVM com -javaagent. No carregamento das classes ele reescreve o bytecode das bibliotecas que conhece — Spring MVC e WebFlux, os clientes HTTP, JDBC e HikariCP, Kafka, Redis, logback, a própria JVM — para que cada requisição vire um span, cada biblioteca reporte métricas com nomes padronizados (as convenções semânticas do OpenTelemetry) e cada linha de log carregue o trace id da requisição que a escreveu.

Baixe-o uma vez em infra/otel/ (são 26 MB: o .gitignore o mantém fora do Git, e cada clone roda o script):

scripts/get-otel-agent.sh
#!/bin/sh
# Downloads the OpenTelemetry Java agent into infra/otel/ (mounted read-only into every Java service).
# Usage, from the repository root: sh scripts/get-otel-agent.sh
set -e
VERSION=2.32.0
mkdir -p infra/otel
curl -fsSL -o infra/otel/opentelemetry-javaagent.jar \
  "https://github.com/open-telemetry/opentelemetry-java-instrumentation/releases/download/v${VERSION}/opentelemetry-javaagent.jar"
ls -l infra/otel/opentelemetry-javaagent.jar
.gitignore
# build output
target/
*.class
# IDEs and OS
.idea/
.vscode/
*.iml
.DS_Store
# local secrets: never commit them
.env
# k6 HTML reports are big; commit the JSON summaries and the tables in results/*.md
results/*.html

As imagens não mudam: o Compose monta infra/otel/ somente leitura em cada serviço Java e liga o agente com variáveis de ambiente compartilhadas por uma âncora YAML:

docker-compose.yaml (excerpt)
# lab 8: OpenTelemetry settings shared by every Java service (merged into each "environment")
x-otel: &otel
  JAVA_TOOL_OPTIONS: -javaagent:/otel/opentelemetry-javaagent.jar
  OTEL_JAVAAGENT_ENABLED: ${OTEL_ON:-true}          # false = same image, agent off
  OTEL_EXPORTER_OTLP_ENDPOINT: http://otel-lgtm:4318
  OTEL_METRIC_EXPORT_INTERVAL: "10000"              # 10 s instead of 60 s
  OTEL_RESOURCE_ATTRIBUTES: service.namespace=boxoffice,deployment.environment.name=local
  OTEL_TRACES_SAMPLER: ${OTEL_TRACES_SAMPLER:-parentbased_always_on}
  OTEL_TRACES_SAMPLER_ARG: ${OTEL_TRACES_SAMPLER_ARG:-1.0}
  LOGGING_PATTERN_CORRELATION: "[%X{trace_id:-},%X{span_id:-}] "   # trace id in console logs

# ... and in every Java service, for example:
  order:
    build: ./services/order
    volumes:
      - ./infra/otel:/otel:ro
    environment:
      <<: *otel
      OTEL_SERVICE_NAME: order
Variável Efeito
JAVA_TOOL_OPTIONS a JVM a lê antes do main: conecta o agente sem mudar a imagem nem o ENTRYPOINT
OTEL_JAVAAGENT_ENABLED false desliga o agente com a mesma imagem — usado no passo Meça
OTEL_SERVICE_NAME o atributo service.name: o nome pelo qual você filtra em todo lugar. As réplicas catalog-1..3 usam todas catalog: um serviço, três instâncias
OTEL_EXPORTER_OTLP_ENDPOINT para onde enviar; o agente usa OTLP sobre HTTP (4318) por padrão
OTEL_METRIC_EXPORT_INTERVAL 10 s em vez dos 60 s padrão, para que os dashboards reajam durante o lab
OTEL_RESOURCE_ATTRIBUTES atributos extras em todo sinal; service.namespace agrupa os serviços do BoxOffice
OTEL_TRACES_SAMPLER quais requisições são rastreadas; todas por padrão (o experimento B do Meça muda isso)
LOGGING_PATTERN_CORRELATION o logging.pattern.correlation do Spring Boot: imprime [trace id,span id] em toda linha do console

O salto que o agente não enxerga: o outbox

Faça um pedido e procure o trace dele no Tempo. Com o código do lab 7 você encontra dois traces sem relação: um para o POST /orders (order → INSERTs) e outro que começa na tarefa agendada do relay do outbox e continua pelo Kafka até o notification. O agente propaga o contexto em chamadas HTTP e mensagens Kafka automaticamente, mas o outbox é uma linha do banco lida depois por outra thread: o contexto da requisição não está na linha, então se perde.

sequenceDiagram
    participant O as order (thread HTTP)
    participant DB as tabela outbox
    participant R as relay (thread do agendador)
    participant K as Kafka
    participant N as notification
    O->>DB: INSERT da linha do outbox + traceparent da requisição
    R->>DB: SELECT da linha (com o seu traceparent)
    Note over R: torna esse contexto o atual
    R->>K: send: o agente injeta o MESMO trace id nos headers
    K->>N: consumo: o agente continua o trace

A correção é a mesma ideia que o W3C Trace Context usa no HTTP: levar o traceparent junto com o dado. Guarde-o na linha do outbox e torne-o o contexto atual quando o relay publicar. Quatro arquivos do order mudam:

package boxoffice.order.outbox;

import tools.jackson.databind.ObjectMapper;
import io.opentelemetry.api.trace.propagation.W3CTraceContextPropagator;
import io.opentelemetry.context.Context;
import java.util.HashMap;
import java.util.Map;
import java.util.UUID;
import org.springframework.jdbc.core.simple.JdbcClient;
import org.springframework.stereotype.Component;
import org.springframework.transaction.annotation.Propagation;
import org.springframework.transaction.annotation.Transactional;

@Component
public class Outbox {

    private final JdbcClient jdbc;
    private final ObjectMapper mapper;

    public Outbox(JdbcClient jdbc, ObjectMapper mapper) {
        this.jdbc = jdbc;
        this.mapper = mapper;
    }

    /** MANDATORY: fails fast if someone calls it outside the business transaction. */
    @Transactional(propagation = Propagation.MANDATORY)
    public void append(UUID eventId, String aggregateType, UUID aggregateId, String eventType, Object payload) {
        String json = mapper.writeValueAsString(payload); // Jackson 3: exceptions are unchecked
        // capture the trace context of the current request (null without the agent)
        Map<String, String> carrier = new HashMap<>();
        W3CTraceContextPropagator.getInstance().inject(Context.current(), carrier, (c, k, v) -> c.put(k, v));

        jdbc.sql("""
                INSERT INTO outbox (id, aggregate_type, aggregate_id, event_type, payload, traceparent)
                VALUES (?, ?, ?, ?, ?::jsonb, ?)
                """)
                .params(eventId, aggregateType, aggregateId, eventType, json, carrier.get("traceparent"))
                .update();
    }
}
services/order/src/main/java/boxoffice/order/outbox/OutboxRelay.java
package boxoffice.order.outbox;

import boxoffice.order.OrderProperties;
import io.opentelemetry.api.trace.propagation.W3CTraceContextPropagator;
import io.opentelemetry.context.Context;
import io.opentelemetry.context.Scope;
import io.opentelemetry.context.propagation.TextMapGetter;
import java.nio.charset.StandardCharsets;
import java.util.ArrayList;
import java.util.List;
import java.util.UUID;
import java.util.concurrent.CompletableFuture;
import java.util.concurrent.TimeUnit;
import org.apache.kafka.clients.producer.ProducerRecord;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.jdbc.core.JdbcTemplate;
import org.springframework.jdbc.core.simple.JdbcClient;
import org.springframework.kafka.core.KafkaTemplate;
import org.springframework.kafka.support.SendResult;
import org.springframework.scheduling.annotation.Scheduled;
import org.springframework.stereotype.Component;
import org.springframework.transaction.annotation.Transactional;

@Component
public class OutboxRelay {

    private static final Logger log = LoggerFactory.getLogger(OutboxRelay.class);

    record Pending(UUID id, UUID aggregateId, String eventType, String payload, String traceparent) {
    }

    /** Reads the "traceparent" key from a Pending row. */
    private static final TextMapGetter<Pending> ROW = new TextMapGetter<>() {
        @Override
        public Iterable<String> keys(Pending p) {
            return List.of("traceparent");
        }

        @Override
        public String get(Pending p, String key) {
            return p == null || !"traceparent".equals(key) ? null : p.traceparent();
        }
    };

    private final JdbcClient jdbc;
    private final JdbcTemplate jdbcTemplate;
    private final KafkaTemplate<String, String> kafka;
    private final String topic;

    public OutboxRelay(JdbcClient jdbc, JdbcTemplate jdbcTemplate,
                       KafkaTemplate<String, String> kafka, OrderProperties props) {
        this.jdbc = jdbc;
        this.jdbcTemplate = jdbcTemplate;
        this.kafka = kafka;
        this.topic = props.topic();
    }

    @Scheduled(fixedDelayString = "${boxoffice.order.relay-interval-ms:200}")
    @Transactional
    public void relay() throws Exception {
        // SKIP LOCKED: several order replicas can relay in parallel without taking the same rows
        List<Pending> batch = jdbc.sql("""
                SELECT id, aggregate_id, event_type, payload::text AS payload, traceparent
                FROM outbox
                WHERE published_at IS NULL
                ORDER BY created_at
                LIMIT 100
                FOR UPDATE SKIP LOCKED
                """)
                .query(Pending.class)
                .list();
        if (batch.isEmpty()) {
            return;
        }

        List<CompletableFuture<SendResult<String, String>>> acks = new ArrayList<>();
        for (Pending p : batch) {
            ProducerRecord<String, String> record =
                    new ProducerRecord<>(topic, p.aggregateId().toString(), p.payload());
            record.headers().add("eventId", p.id().toString().getBytes(StandardCharsets.UTF_8));
            record.headers().add("eventType", p.eventType().getBytes(StandardCharsets.UTF_8));
            // continue the trace of the request that created the event
            Context origin = W3CTraceContextPropagator.getInstance().extract(Context.root(), p, ROW);
            try (Scope ignored = origin.makeCurrent()) {
                acks.add(kafka.send(record)); // the agent's producer span is a child of the request
            }
        }
        // wait for every ack; on failure the transaction rolls back and the rows are retried
        CompletableFuture.allOf(acks.toArray(new CompletableFuture<?>[0])).get(10, TimeUnit.SECONDS);

        jdbcTemplate.batchUpdate("UPDATE outbox SET published_at = clock_timestamp() WHERE id = ?",
                batch.stream().map(p -> new Object[] {p.id()}).toList());
        log.info("relayed {} event(s) to {}", batch.size(), topic);
    }

    @Scheduled(cron = "0 0 * * * *")
    @Transactional
    public void purge() {
        int n = jdbcTemplate.update(
                "DELETE FROM outbox WHERE published_at < now() - interval '1 day'");
        log.info("purged {} published outbox row(s)", n);
    }
}

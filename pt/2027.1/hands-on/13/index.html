Neste lab

  • Adicionar cinco etapas de IA ao pipeline do BoxOffice do lab 11: um revisor de pull requests, um gerador de testes avaliado por testes de mutação, um agente que propõe uma correção quando o CI falha, release notes a cada tag e um veredito de canary explicado.
  • Executar todas as etapas por meio de um cliente pequeno e neutro em relação ao provedor: um modelo local com o Ollama (gratuito, o padrão), o Claude pelo SDK oficial, ou qualquer endpoint compatível com OpenAI pelo LiteLLM.
  • Endurecer os workflows: permissões, gatilhos, segredos e um teste de prompt injection ao qual o revisor precisa resistir.
  • Medir: precisão das revisões, custo por PR, minutos de CI e tempo até o merge ao longo de uma semana de pull requests.

O lab 11 deu ao BoxOffice um pipeline que compila, testa, escaneia, assina e libera cada mudança por trás de um canary. O lab 12 colocou um modelo de linguagem dentro do produto. Este lab coloca modelos de linguagem dentro do pipeline — e os trata com a mesma disciplina de qualquer outra dependência: privilégio mínimo, orçamentos, validação de toda saída e números que digam se eles ajudam. Na história da disciplina ele constrói o capítulo 14: as decisões de revisão de código, testes gerados por IA, agentes no CI, liberação e operação e segurança e governança.

A regra do lab inteiro: a IA propõe; regras e humanos decidem. Nenhuma etapa deste lab consegue fazer merge, aprovar, fazer deploy ou rollback sozinha. O modelo escreve comentários, patches e explicações; verificações determinísticas (testes, score de mutação, limites da política) e pessoas decidem.

Antes de começar
Tempo 6–8 horas para as partes 0–6 (uma parte por sessão é ok), mais ~15 minutos por dia durante uma semana na parte 7
Você precisa das ferramentas do lab 0; de uma conta no GitHub (o repositório no GitHub, a CLI gh autenticada); para o modelo gratuito, ~6 GB de RAM livre e ~5 GB de disco (máquinas de 8 GB: veja Solução de problemas)

Toda etapa de IA tem a mesma forma — um gatilho, a coleta de contexto, uma chamada ao modelo (ou um loop de agente limitado) com saída estruturada, a validação e uma ação com a menor permissão possível:

Parte Gatilho Contexto Saída Validada por Ação (permissão)
1. Review por IA pull_request diff numerado, CONVENTIONS.md, ADRs achados em JSON só linhas adicionadas, limites, deduplicação comentários de review (pull-requests: write)
2. Testes por IA label ai-tests classe, vizinhas, testes existentes uma classe de teste compila, passa duas vezes, score do PIT sobe PR em rascunho (job separado)
3. Agente de correção workflow_run com falha log da falha, repositório um patch mvn verify, nenhum teste removido, só src/ PR em rascunho (job separado)
4. Release notes tag v* commits, diffstat, migrations itens em JSON com referências todo item cita um commit real release em rascunho (contents: write)
5. Canary etapa de análise números do Prometheus explicação precisa repetir o veredito da política nenhuma: a política decide
6. Segurança — — — golden set + casos de injection —
7. Meça semanal histórico de PRs relatório — —

0. Setup: um cliente, três formas de chegar a um modelo

Todos os scripts ficam em .github/ai/ do seu repositório e importam um único módulo, llm.py. Ele esconde o provedor atrás de uma única função, complete_json(system, user, schema), que devolve JSON validado contra um schema junto com o uso de tokens e o seu custo. O provedor é escolhido por variáveis de ambiente — os mesmos nomes localmente e no GitHub Actions (como variables do repositório):

Variável Padrão Significado
LLM_PROVIDER ollama ollama (local, gratuito), anthropic (Claude) ou openai (qualquer endpoint compatível com OpenAI, ex.: LiteLLM)
LLM_MODEL qwen2.5-coder-16k no ollama, claude-opus-5-5 no anthropic o id do modelo
LLM_BASE_URL http://localhost:11434/v1 no ollama endpoint de ollama / openai
LLM_API_KEY, ANTHROPIC_API_KEY — segredos, só para os caminhos pagos ou remotos

0.1 Escolha um modelo

  1. Instale o Ollama e inicie-o:

    # macOS
brew install ollama && brew services start ollama
# Linux and Windows (inside WSL 2)
curl -fsSL https://ollama.com/install.sh | sh

    Verifique se o servidor responde: curl -s http://localhost:11434/api/version imprime {"version":"..."}. No Linux sem systemd (algumas instalações de WSL), inicie-o à mão em outro terminal com ollama serve.

  2. Baixe o modelo — depois de salvar os arquivos do passo 0.2 (o script é um deles):

    bash .github/ai/ollama-model.sh

    Ele baixa o qwen2.5-coder:7b (4,7 GB, uma vez) e cria o qwen2.5-coder-16k, o mesmo modelo com uma janela de contexto de 16.384 tokens. A janela padrão do Ollama é de 4.096 tokens, e um prompt maior é cortado em silêncio — o revisor perderia as instruções num diff grande. No final, você deve ver:

    success
ready: LLM_PROVIDER=ollama LLM_MODEL=qwen2.5-coder-16k (context 16384 tokens)

Nada mais a configurar: ollama é o provedor padrão. No GitHub Actions, os workflows instalam o Ollama no runner com a action composta .github/actions/ollama (abaixo) — de graça, mas devagar: um runner só com CPU precisa de minutos por chamada, onde o seu notebook precisa de segundos. Espere uma qualidade de review menor que a de um modelo de fronteira; a parte 6 mede quanto menor.

  1. Crie uma chave de API no Claude Console e defina um limite de gasto mensal para o workspace dela (alguns dólares bastam para este lab).
  2. Localmente: export LLM_PROVIDER=anthropic e export ANTHROPIC_API_KEY=<a chave que você acabou de criar> (nunca faça commit dela; o .gitignore do lab 0 já ignora .env).

  3. No GitHub: Settings → Secrets and variables → Actions, ou com o gh:

    gh secret set ANTHROPIC_API_KEY          # paste the key when asked
gh variable set LLM_PROVIDER --body anthropic
gh variable set LLM_MODEL --body claude-opus-5-5   # or claude-sonnet-5-5 / claude-haiku-4-5: cheaper

O cliente chama a Messages API pelo SDK oficial anthropic com saídas estruturadas (output_config.format com um JSON schema), prompt caching do prompt de sistema e o fallback de recusa do lado do servidor (um beta) nos modelos que o suportam. Consulte a visão geral dos modelos para os ids e preços atuais.

O proxy LiteLLM do lab 12 expõe um endpoint compatível com OpenAI na frente de qualquer provedor. Localmente: export LLM_PROVIDER=openai LLM_BASE_URL=http://localhost:4000/v1 LLM_MODEL=<um alias de modelo do seu proxy> e export LLM_API_KEY=<a sua chave virtual do LiteLLM>; curl -s -H "Authorization: Bearer $LLM_API_KEY" $LLM_BASE_URL/models lista os aliases.

Runners hospedados pelo GitHub não alcançam o localhost do seu notebook: no CI, esse caminho exige um proxy LiteLLM acessível pela internet (ou um runner self-hosted). Defina as variáveis de repositório LLM_PROVIDER=openai, LLM_BASE_URL, LLM_MODEL e o segredo LLM_API_KEY (uma chave virtual com orçamento próprio).

E o GitHub Models?

Versões anteriores deste lab podiam usar o GitHub Models, uma API de inferência gratuita para o Actions. O GitHub o desativou em 30 de julho de 2026 (documentação do GitHub), então o caminho gratuito agora é o Ollama.

O que custa dinheiro

Item Custo
Ollama na sua máquina gratuito (energia, ~5 GB de disco)
Minutos do GitHub Actions gratuitos em repositórios públicos; num repositório privado contam na cota mensal do seu plano (cobrança do GitHub) — o caminho do Ollama usa vários minutos de runner por job de IA
API do Claude (LLM_PROVIDER=anthropic, e o caminho A da parte 3) paga por token; proteja-a com um limite de gasto no workspace. Cada job imprime o seu custo em US$
Um proxy LiteLLM na internet o que o provedor por trás dele cobrar

Política do curso para este lab

Use a sua própria chave ou um modelo local, nunca a de um colega ou de uma empresa. Nunca cole segredos, dados reais de clientes ou dados pessoais em prompts. Todo commit que contém código gerado por IA leva o trailer AI-assisted: <tool> (<model>) e todo PR aberto por IA leva o label ai-generated.

#!/usr/bin/env bash
# Prepare the free local model of lab 13 (run it from the repository root):
#
#     bash .github/ai/ollama-model.sh
#
# Pulls qwen2.5-coder:7b (4.7 GB) and creates `qwen2.5-coder-16k`: the same weights with a
# 16,384-token context window. Ollama's default window is 4,096 tokens, and a longer prompt
# (conventions + a big diff, or an agent's growing conversation) is cut SILENTLY.
set -euo pipefail

BASE="${OLLAMA_BASE_MODEL:-qwen2.5-coder:7b}"
NAME="${OLLAMA_MODEL_NAME:-qwen2.5-coder-16k}"
CTX="${OLLAMA_NUM_CTX:-16384}"

ollama pull "$BASE"
modelfile="$(mktemp)"
printf 'FROM %s\nPARAMETER num_ctx %s\n' "$BASE" "$CTX" > "$modelfile"
ollama create "$NAME" -f "$modelfile"
rm -f "$modelfile"
echo "ready: LLM_PROVIDER=ollama LLM_MODEL=$NAME (context $CTX tokens)"
.github/actions/ollama/action.yml
name: Local model (Ollama)
description: >-
  Free path of lab 13. Installs Ollama on the runner and prepares qwen2.5-coder-16k.
  CPU only: expect minutes per call, not seconds.
runs:
  using: composite
  steps:
    - name: Install and start Ollama
      shell: bash
      run: |
        curl -fsSL https://ollama.com/install.sh | sh
        if ! curl -sf http://localhost:11434/api/version > /dev/null; then
          (ollama serve > "$RUNNER_TEMP/ollama.log" 2>&1 &)
        fi
        for _ in $(seq 1 30); do
          curl -sf http://localhost:11434/api/version && break
          sleep 1
        done
    - name: Prepare the model
      shell: bash
      run: bash .github/ai/ollama-model.sh

"""Provider-neutral LLM client for the BoxOffice CI jobs.

LLM_PROVIDER=ollama     (default) a local model through Ollama's OpenAI-compatible API: free, no key
                        (LLM_BASE_URL defaults to http://localhost:11434/v1)
LLM_PROVIDER=anthropic  Claude Messages API through the official SDK (needs ANTHROPIC_API_KEY)
LLM_PROVIDER=openai     any other OpenAI-compatible endpoint, e.g. a LiteLLM proxy
                        (needs LLM_BASE_URL; LLM_API_KEY if the endpoint wants one)
LLM_MODEL               model id: qwen2.5-coder-16k (see ollama-model.sh), claude-opus-5-5, ...

Every call returns parsed JSON that validates against a JSON Schema, plus the token
usage, so each job can print what it cost.
"""
from __future__ import annotations

import json
import os
import sys
import time
from dataclasses import dataclass

import jsonschema

# US$ per million tokens: (input, output, cache read). List prices when this lab was
# written -- illustrative; check the provider's pricing page. Unknown models cost 0 here
# (a local Ollama model costs runner minutes, not tokens).
PRICES = {
    "claude-opus-5-5": (4.00, 20.00, 0.20),
    "claude-sonnet-5-5": (2.00, 10.00, 0.20),
    "claude-haiku-4-5": (1.00, 5.00, 0.10),
}
CACHE_WRITE = 1.25  # a 5-minute cache write costs 1.25x the input price
# Models that accept the server-side refusal fallback (beta); see the Claude docs.
FALLBACK_MODELS = {"claude-opus-5-5", "claude-sonnet-5-5"}


class LLMError(RuntimeError):
    """The model did not return a usable answer (refusal, truncation, invalid JSON)."""


@dataclass
class Usage:
    model: str
    input_tokens: int = 0        # uncached input
    cache_read_tokens: int = 0
    cache_write_tokens: int = 0
    output_tokens: int = 0       # includes thinking tokens, billed as output
    calls: int = 0
    seconds: float = 0.0

    def add(self, other: "Usage") -> None:
        for f in ("input_tokens", "cache_read_tokens", "cache_write_tokens",
                  "output_tokens", "calls", "seconds"):
            setattr(self, f, getattr(self, f) + getattr(other, f))

    @property
    def usd(self) -> float:
        price = PRICES.get(self.model)
        if price is None:
            return 0.0
        p_in, p_out, p_read = price
        return (self.input_tokens * p_in + self.cache_write_tokens * p_in * CACHE_WRITE
                + self.cache_read_tokens * p_read + self.output_tokens * p_out) / 1e6

    def as_dict(self) -> dict:
        return {"model": self.model, "calls": self.calls, "in": self.input_tokens,
                "cache_read": self.cache_read_tokens, "cache_write": self.cache_write_tokens,
                "out": self.output_tokens, "seconds": round(self.seconds, 1),
                "usd": round(self.usd, 4)}

    def markdown(self) -> str:
        price = "n/a (local or unknown model)" if self.model not in PRICES else f"US$ {self.usd:.4f}"
        return ("| Model | Calls | Input | Cache read | Cache write | Output | Time | Cost |\n"
                "|---|---|---|---|---|---|---|---|\n"
                f"| `{self.model}` | {self.calls} | {self.input_tokens:,} | {self.cache_read_tokens:,}"
                f" | {self.cache_write_tokens:,} | {self.output_tokens:,} | {self.seconds:.1f} s"
                f" | {price} |\n")


def provider() -> str:
    return os.environ.get("LLM_PROVIDER") or "ollama"     # the free path is the default


def model() -> str:
    default = "qwen2.5-coder-16k" if provider() == "ollama" else "claude-opus-5-5"
    return os.environ.get("LLM_MODEL") or default


def base_url() -> str:
    """Endpoint of the OpenAI-compatible providers (ollama, openai)."""
    url = os.environ.get("LLM_BASE_URL") or (
        "http://localhost:11434/v1" if provider() == "ollama" else "")
    if not url:
        raise LLMError("LLM_PROVIDER=openai needs LLM_BASE_URL (e.g. http://localhost:4000/v1)")
    return url


def complete_json(system: str, user: str, schema: dict, *, max_tokens: int = 16000,
                  effort: str = "medium") -> tuple[dict, Usage]:
    """One model call that must answer with JSON valid against `schema`.

    `system` should be stable across runs (it is cached); `user` carries the data
    of this run (diff, logs, metrics), which is untrusted.
    """
    start = time.monotonic()
    try:
        if provider() == "anthropic":
            data, usage = _anthropic(system, user, schema, max_tokens, effort)
        else:
            data, usage = _openai_compatible(system, user, schema, max_tokens)
    except LLMError:
        raise
    except Exception as err:  # no key, connection refused, quota... -> the caller fails open
        raise LLMError(f"{type(err).__name__}: {str(err)[:300]}") from err
    usage.seconds = time.monotonic() - start
    return data, usage


def _anthropic(system, user, schema, max_tokens, effort):
    import anthropic

    client = anthropic.Anthropic()          # reads ANTHROPIC_API_KEY
    name = model()
    output_config = {"format": {"type": "json_schema", "schema": schema}}
    if "haiku" not in name:                 # the effort parameter is not available on Haiku 4.5
        output_config["effort"] = effort
    request = dict(
        model=name,
        max_tokens=max_tokens,
        # The system prompt (instructions + conventions) is the same on every run:
        # mark it for prompt caching so repeated runs pay the cheap cache-read price.
        system=[{"type": "text", "text": system, "cache_control": {"type": "ephemeral"}}],
        messages=[{"role": "user", "content": user}],
        output_config=output_config,
    )
    if name in FALLBACK_MODELS:
        # If a safety classifier declines the request, the API re-runs it on a fallback model.
        response = client.beta.messages.create(
            betas=["server-side-fallback-2026-07-01"], fallbacks="default", **request)
    else:
        response = client.messages.create(**request)

    if response.stop_reason == "refusal":
        raise LLMError("the model declined the request")
    if response.stop_reason == "max_tokens":
        raise LLMError("answer truncated: raise max_tokens or send less context")
    text = next((b.text for b in response.content if b.type == "text"), "")
    data = _parse(text, schema)
    u = response.usage
    usage = Usage(name, input_tokens=u.input_tokens,
                  cache_read_tokens=u.cache_read_input_tokens or 0,
                  cache_write_tokens=u.cache_creation_input_tokens or 0,
                  output_tokens=u.output_tokens, calls=1)
    return data, usage


def _openai_compatible(system, user, schema, max_tokens):
    from openai import OpenAI

    client = OpenAI(base_url=base_url(), api_key=os.environ.get("LLM_API_KEY") or "not-needed")
    name = model()
    # JSON mode is widely supported (LiteLLM, Ollama, vLLM); the schema goes in the
    # prompt and the answer is validated here, with one repair attempt.
    instructions = (system + "\n\nAnswer with ONE JSON object, and nothing else, that validates "
                    "against this JSON Schema:\n" + json.dumps(schema))
    messages = [{"role": "system", "content": instructions}, {"role": "user", "content": user}]
    usage = Usage(name)
    for attempt in range(2):
        response = client.chat.completions.create(
            model=name, max_tokens=max_tokens, temperature=0,
            response_format={"type": "json_object"}, messages=messages)
        usage.calls += 1
        if response.usage:
            usage.input_tokens += response.usage.prompt_tokens
            usage.output_tokens += response.usage.completion_tokens
        text = response.choices[0].message.content or ""
        try:
            return _parse(text, schema), usage
        except LLMError as err:
            if attempt == 1:
                raise
            messages += [{"role": "assistant", "content": text},
                         {"role": "user", "content": f"Invalid answer: {err}. Reply again with "
                                                     "only the JSON object."}]
    raise AssertionError("unreachable")


def _parse(text: str, schema: dict) -> dict:
    try:
        data = json.loads(text)
        jsonschema.validate(data, schema)  # defence in depth, even with structured outputs
    except (json.JSONDecodeError, jsonschema.ValidationError) as err:
        raise LLMError(f"answer is not valid JSON for the schema: {str(err)[:200]}") from err
    return data


def step_summary(markdown: str) -> None:
    """Append Markdown to the job summary page (or print it when running locally)."""
    path = os.environ.get("GITHUB_STEP_SUMMARY")
    if path:
        with open(path, "a", encoding="utf-8") as f:
            f.write(markdown + "\n")
    else:
        print(markdown, file=sys.stderr)

0.3 O contexto: convenções e decisões

O revisor só é tão bom quanto o que ele sabe sobre o seu sistema. Um modelo genérico conhece Java; ele não sabe que order nunca deve escrever no schema inventory. Escreva esse conhecimento uma vez — para humanos, antes de tudo — em CONVENTIONS.md, na raiz do repositório:

CONVENTIONS.md
# BoxOffice conventions

Read by humans and by the AI reviewer. Keep it short: every line costs tokens on every review.

## Architecture rules (blocker if violated)
- One PostgreSQL schema per service (`catalog`, `inventory`, `orders`, `payment`, ...).
  A service reads and writes ONLY its own schema. Another service's data is reached
  through its HTTP API or its events, never with SQL.
- Seat state (holds, sales) is owned by `inventory`. Any change to a seat goes through
  inventory, inside a transaction that locks the row (`SELECT ... FOR UPDATE`) or uses
  optimistic locking. Double booking is the worst bug this system can have.
- `order` publishes events through the transactional outbox, never directly to Kafka
  inside a database transaction.
- Every outbound HTTP call (service-to-service or to the payment provider) has a connect
  and a read timeout, and calls to `payment` are idempotent (Idempotency-Key header).
- Services trust identity only from the `X-User-*` headers set by the gateway.

## Code
- Java 21, Spring Boot 4.1, Spring Cloud 2025.1; DTOs are `record`s; no Lombok.
- Money is `long` cents or `BigDecimal`, never `double`.
- SQL uses bind parameters; never build SQL by string concatenation.
- No secrets in code or in application.yaml: read them from environment variables.
- Errors are RFC 9457 problem+json; `POST` that creates returns 201 with `Location`.
- Flyway migrations are append-only: never edit a migration that was merged.

## Tests
- Business rules in `inventory`, `order` and `payment` need unit tests for the error paths.
- No `Thread.sleep` in tests; inject a `Clock` for time.

Os registros de decisão de arquitetura (ADRs) em docs/adr/ também são enviados ao revisor (os primeiros 3.000 caracteres de cada um). Um ADR é uma nota curta sobre uma decisão: contexto, decisão, consequências. Comece pela que o BoxOffice tomou no lab 1:

docs/adr/0001-schema-per-service.md
# ADR 0001 — One database schema per service

- Status: accepted
- Date: 2027-02-15

## Context
All BoxOffice services share one PostgreSQL instance (`db`, database `boxoffice`). Nothing in
PostgreSQL stops `order` from reading or updating `inventory.seats` directly, and a shortcut like
that would couple the two services' release cycles and bypass inventory's locking rules.

## Decision
Each service owns one schema (`catalog`, `inventory`, `orders`, `payment`, `notification`, `auth`)
and its Flyway migrations. A service reads and writes ONLY its own schema. Data owned by another
service is reached through that service's HTTP API or its events.

## Consequences
- A query across services becomes an API call or a read model built from events (slower, explicit).
- Each schema can move to its own database later without changing other services.
- Reviewers (human and AI) treat SQL that names another service's schema as a blocker.

Partes

  1. Review de pull request por IA — achados estruturados como comentários inline, controle de ruído, custo no resumo do job.
  2. Testes gerados por IA, avaliados por testes de mutação — manter um teste gerado só se o PIT disser que ele pega mais bugs.
  3. Um agente que corrige o build quebrado — Claude Code headless ou um loop de agente de 150 linhas; um PR em rascunho para um humano.
  4. Release notes por IA — ancoradas nos commits, publicadas como rascunho.
  5. Um veredito de canary explicado — a política decide, o modelo explica.
  6. Endurecimento de segurança — gatilhos, permissões, segredos, prompt injection e uma avaliação com golden set.
  7. Meça — precisão, US$/PR, minutos de CI e tempo até o merge ao longo de uma semana.
  8. Quiz.

Boas práticas neste lab

  • A IA propõe, as regras decidem — o .github/ai/review.py publica event: COMMENT, nunca uma aprovação, e sai com 0 quando o modelo falha; por quê: Revisão de código.
  • Privilégio dividido por job — o ai-fix.yaml roda o modelo com um token só de leitura e abre o PR rascunho num job sem modelo; por quê: Agentes no CI.
  • Testes gerados provam o seu valor — o gen_tests.py só mantém um teste se ele passa duas vezes e acrescenta 5 pp de mutation score; por quê: Testes.
  • O veredito é código; o modelo só explica — o canary_explain.py devolve o exit code da política e descarta uma explicação que discorde; por quê: Liberação e operação.
  • As ferramentas de IA têm o seu próprio teste de regressão — o eval_review.py e o ai-eval.yaml rodam o golden set quando o prompt, as convenções ou o modelo mudam; por quê: Segurança e governança.

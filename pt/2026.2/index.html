Avaliação

\[ \text{Nota Final} = \left\{\begin{array}{lll} \text{Individual} \geq 5 \bigwedge \text{Equipe} \geq 5 & \implies & \displaystyle \frac{ \text{Individual} + \text{Equipe} } {2} \\ \\ \text{Caso contrário} & \implies & \min\left(\text{Individual}, \text{Equipe}\right) \end{array}\right. \]

  1. Quizzes: a disciplina terá 3 quizzes; a menor nota é descartada e a nota final é a média das duas melhores:

    \[ \text{Quizzes} = \frac{\text{Q}_1 + \text{Q}_2 + \text{Q}_3 - \min(\text{Q}_1, \text{Q}_2, \text{Q}_3)}{2} \]

  2. Microsserviço: os estudantes terão de implementar um microsserviço. A nota é dada por conceito, com base nas Notas da Engenharia:

    Conceito Nota
    A (+) 9 (10)
    B (+) 7 (8)
    C (+) 5 (6)
    D 4
    I 0

  3. Equipe: a equipe deve ser composta por 2 a 3 integrantes. A nota da equipe será a mesma para todos os integrantes e se baseia na entrega do projeto e na documentação.

    Cadastro dos grupos

    Prazo para o cadastro: 4 de setembro de 2026.

    Equipes de 2 a 3 integrantes.

    Crie um repositório no GitHub para compartilhar o código e a documentação do projeto.

    Isto é OBRIGATÓRIO para organizar as equipes e as contas da AWS.

    Nome do repositório

    Escolha um nome profissional, por exemplo, platform, microservices, cloud-native-ecommerce.

    O repositório deve estar vinculado aos autores no GitHub (git config).

  4. Documentação: a documentação do projeto é avaliada pela qualidade, completude e apresentação profissional. Ela deve cobrir arquitetura, decisões de design, implementação, testes e observabilidade. O objetivo é uma peça de portfólio que possa ser implantada.

    Requisitos da documentação

    Prazo de entrega: 16 de novembro de 2026.

    A documentação DEVE ser hospedada no GitHub Pages (pública).

    Use o tema MkDocs Material.

    Template de entrega: template de documentação.

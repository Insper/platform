\ans{1} \final{F: (a) and (e)}: they describe what the system does and become APIs and data. \final{NF}: (b) latency and scalability (a percentile at a load level); (c) consistency; (d) durability; (f) cost; (g) operability (and availability); (h) consistency (a bounded staleness that lets the catalog be cached). \careful{calling (c) functional because it ``sounds like a rule''. ``At most once'' is a consistency guarantee: it decides the database and the locking, not an endpoint.}
\ans{2} (a) ``Search \final{p99 $<$ 250 ms at 800 queries/s}; results may lag the catalog by up to 5 min.'' \careful{an adjective with no number, no percentile, no window or no load level. ``p99 $<$ 250 ms'' with no request rate is still untestable.}
\ans{3} (a) $200 \times 0.5$ ms $=$ \final{100 ms} just waiting on the network: fix the N$+$1 with one query (a join or \texttt{IN}). (b) The database now sees 5\% of the reads: \final{20$\times$ fewer}. (c) $1\,000 \times 5\% =$ \final{50 reads/s}: \final{the cache first}, replicas only if writes or misses still load the primary. (d) 1 GB/s $=$ \final{8 Gbit/s}, a whole network card: put a \final{CDN with an object store} in front of the posters.
\careful{reading ``95\% hit ratio'' as ``5\% better''. The number that matters is the miss ratio: the database load falls from 100\% to 5\%.}
\ans{4} (a) \final{Load Balancer $+$ stateless App Server replicas $+$ Health Check}; session state must leave the server. (b) \final{Read replicas}; replication lag and stale reads. (c) \final{Message Queue $+$ Worker}; duplicates (at-least-once), backlog, ordering. (d) \final{A waiting room} (a queue admitting $\approx$ 1\,000 fans/s); fans wait in line, and the line must be fair. (e) \final{Services along business boundaries, API Gateway, Event Stream}; network calls fail and data is distributed. (f) \final{WAF, rate limiting} (per fan, IP, card); false positives on real fans.
\careful{scaling the wrong tier: adding app replicas when the measured symptom is in the database.}
\ans{5} (a) $2 \times 10^6 \times 20 = 4 \times 10^7$ reads/day $\to$ \final{400/s, $\approx$ 1\,200/s at the peak}. (b) $10^5 / 10^5 \approx$ \final{1 order/s}: reads outnumber writes by hundreds. (f) Minutes 5--9, right after clarifying; then the API and the data model (9--14).
\careful{estimating for its own sake: every line of arithmetic must end with the decision it supports.}

\ansclass{14}{AI-Assisted Delivery}
\ans{1} (a) \final{Level 4} (autonomous within guardrails) if CI is trustworthy: small blast radius, fully verified by the build and tests. (b) \final{Level 2 at most} (reviewer/drafter): a concurrency bug sells a seat twice and tests rarely catch races; a human designs it. (c) \final{Level 3} (draft PR): low risk, but a native speaker must review the text. (d) \final{The human who merged} is accountable; the agent only proposed. A deterministic rule, such as ``a fix PR may not delete or skip tests'' (a policy check on the diff) or a required mutation/coverage check, stops it; a sentence in the prompt does not.
\careful{choosing the autonomy by how good the model is, instead of by blast radius and verifiability of the change.}
\ans{2} \final{Trigger}: PR opened or updated (synchronize), not drafts and not forks. \final{Trusted context}: \texttt{CONVENTIONS.md}, ADRs, ownership. \final{Untrusted}: the diff and the PR text (they may carry an injection). \final{Output}: findings in a JSON schema, only on added lines, validated before posting, one review per push. \final{Action}: \texttt{pull-requests: write}, comments only, \final{never approves}. \final{Budget}: about 10 min and US\$ 0.02, through the LLM gateway; \final{fail open} (advisory).
\careful{giving the reviewer \texttt{contents: write} or the right to approve ``to make it work'': the permission is the worst case of every injection.}
\ans{3} (a) $8\,000 \times 2 \times 1.25 + 6\,000 \times 2 + 1\,500 \times 10 = 47\,000$ micro-dollars: \final{US\$ 0.047}. (b) $6\,400 \times 0.20 + 1\,600 \times 2 \times 1.25 + 12\,000 + 15\,000 = 32\,280$: \final{US\$ 0.032}. (c) \final{$\approx$ US\$ 8 a month} for BoxOffice and \final{$\approx$ US\$ 650} for 500 engineers. (d) Output is $15\,000/32\,280 \approx$ \final{46\%} of the bill: each output token costs 5$\times$ an input token (``no praise, no restating'' is a cost optimization too). (e) $0.6 \times 4 \times 5\,000 = 12\,000$ useless comments, \final{200 hours a week}: five full-time engineers. \final{Attention costs far more than tokens.}
\careful{judging an AI step by its token bill and ignoring the people who read its output.}
\ans{4} (a) $\ge$ high: \final{0.6 per PR, 80\%, 32\%}; $\ge$ medium: \final{1.5, 62\%, 62\%}; everything: \final{3.0, 41\%, 82\%}. (b) \final{Start at high $+$ medium}: 1.5 comments per PR, 6 in 10 useful. Everything means 3 comments per PR with 4 in 10 useful: people stop reading all of them, the good ones included. High only misses two thirds of the problems. (c) \final{Shadow} (findings logged, not posted; measure on a golden set) $\to$ \final{advisory} (posted to volunteer teams; measure accepted vs dismissed) $\to$ \final{gate} only the high-precision categories (secrets, injection, cross-boundary calls). A gate is a \final{required check that can fail, never an approval}.
\careful{maximizing recall for a tool that talks to humans: low precision makes the whole channel ignored.}
\ans{5} (a) $82/200 =$ \final{41\%}. (b) A: $84/200 = 42\%$, \final{+1 pp: reject}, despite 95\% coverage (the tests execute code but check little). B: $96/200 = 48\%$, \final{+7 pp: accept}. (c) The test copied the behaviour of the code (the bug) as the expected value: \final{AI wrote the inputs and the oracle came from the code}. The oracle must come from the specification (``a hold lasts 10 minutes'') or from a human. (d) $60 \times 3/5 =$ \final{36 runs/day}; $36 \times (25 - 4) =$ \final{756 min $\approx$ 12.6 runner-hours saved a day}. (e) $36 \times 5 \times 0.04 \times 0.05 \approx$ \final{0.36 per week}, one break every three weeks reaches the nightly run; \final{the full suite after merge (or nightly) catches what selection misses}.
\careful{celebrating coverage: 95\% coverage with a 41\% mutation score means the tests run the code without checking it.}
\ans{6} (a) $\sum_{i=1}^{n} [20\,000 + 2\,500(i-1)] = 20\,000\,n + 2\,500\,n(n-1)/2$. 10 turns: 312\,500 input tokens $\times$ \$4 $=$ \$1.25, plus $4\,000 \times$ \$20 $=$ \$0.08: \final{US\$ 1.33}. 40 turns: $2\,750\,000 \times 4 = \$11.00$ plus \$0.32: \final{US\$ 11.32}, 8.5$\times$ for 4$\times$ the turns. (b) With caching, the repeated prefix is read at \$0.20 instead of \$4 (20$\times$ cheaper); only the new 2\,500 tokens per turn pay full price, so the cost becomes \final{nearly linear} in turns. (c) $0.80/0.25 =$ \final{US\$ 3.20 per merged fix}. (d) \final{Turns 20--30} (\texttt{--max-turns} or the loop bound), \final{US\$ 1--2 per run} (harness token counter plus a provider spend limit), \final{20--30 min of wall time} (job timeout), \final{1 run per commit} (dedupe on the SHA) and a daily quota per repository in the LLM gateway.
\careful{writing the budget in the prompt (``stop after 10 steps''): only the harness can enforce it.}
\ans{7} (a) A good drawing has: the red build as trigger, deduplicated by commit SHA (queue); the agent in a sandboxed runner with a tool allow-list, no secrets and \final{no write token}; model calls through the LLM gateway with quotas; budgets in the orchestrator; verification outside the agent (rebuild, tests, no deleted tests); a \final{separate privileged job} that opens the \final{draft PR} on branch \texttt{ai-fix/<sha8>}; an audit log of every run. (b) \final{Untrusted input} (the PR title from a fork), \final{secrets} and \final{a way to act} (the privileged \texttt{pull\_request\_target} context with write access): a ``pwn request''. Remove at least one leg: no secrets and no write token in the job that reads untrusted text, and pass the title through an environment variable, never inside \texttt{run:}. (c) \final{The canary analysis decides} with thresholds and statistics (29$\times$ the error ratio, p99 2.3$\times$): abort. The AI step only \final{explains} (the 409 errors in \texttt{confirmHold}, links to evidence) and must repeat the verdict, not override it.
\careful{letting an LLM judge the canary or approve the merge: the model proposes and explains, policies and people decide.}
